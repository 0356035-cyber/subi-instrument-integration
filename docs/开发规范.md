# 开发规范

> **用途：** 编码、目录、命名、依赖、运行与测试约定。  
> **何时读：** 动手改代码前；不确定文件应落在哪时。  
> **关联：** 文件索引见 [代码地图.md](./代码地图.md)；Codex 入口见 [README_FOR_CODEX.md](../README_FOR_CODEX.md)。

**更新日期：** 2026-07-06

---

## 1. 仓库职责

| 需求类型 | 仓库 | 目录倾向 |
|----------|------|----------|
| 项目 / 资料 / 数据集 / 分析 / 报告 / AI / 权限 | `subi_knowledge_platform` | `backend/<域>/`、`frontend/*_pages.py` |
| 培训 / 考核 / 授权 / 资质 API | `instrument-training-home` | `app/`、`streamlit_app/` |
| Compose / 备份 / 部署脚本 | 整合仓 `C:\projects` | 根目录 |

**禁止：** 在 `frontend/app.py` 单文件追加数百行新域逻辑。

---

## 2. 目录与命名

### Sub-I 后端

- 入口：`backend/main.py`（逐步 `include_router` 拆分）
- 稳定域：`schedule_*.py`、`document_*.py`、`integrations/`
- 权限：`permissions.py`、`permission_migrations.py`、`role_seed.py`
- 新域规划：`backend/datasets/`、`analysis/`、`reports/`、`ai_workspace/`

### Sub-I 前端

- 主壳：`frontend/app.py`
- 按域拆分：`project_management.py`、`schedule_*.py`、`qualification_inquiry.py`
- 规划：`dataset_pages.py`、`analysis_pages.py`、`report_pages.py`、`ai_workspace.py`

### 数据库迁移

- 项目相关：`project_migrations.py`
- 排班相关：`schedule_migrations.py`
- 权限相关：`permission_migrations.py`
- 新模块：各域 `migrations.py`

## 3. 硬约束（不可违反）

1. 不合并 `instrument-training-home` 进 Sub-I
2. Sub-I 前端只调 8001；培训 JWT 仅存 `.env`
3. 不删除稳定能力除非文档明确废弃
4. 统计最终结论经规则引擎 + 人审
5. `*.db`、`uploads/` **不提交 Git**
6. `role` ≠ `job_title`；项目负责人靠 `owner_employee_id`
7. 极空间保持 `docker compose` 一键四容器

```env

INSTRUMENT_TRAINING_SERVICE_EMPLOYEE_ID=3267

```

```bash
cd subi_knowledge_platform/backend && pip install -r requirements.txt
cd ../frontend && pip install -r requirements.txt
```

## 5. 运行方式

### 推荐：Docker 四容器

```bat
C:\projects\启动系统.bat
```

或 `start-docker.bat`。

### 本地 Python（调试用）

```bat
subi_knowledge_platform\启动资料库系统.bat
```

先启后端（8001），再启前端（8510）；资质查询需培训 API（8000）。

### 验证清单

| 检查项 | 地址 |
|--------|------|
| Sub-I 前端 | http://localhost:8510 |
| Sub-I API | http://localhost:8001/health |
| 培训前端 | http://localhost:8501 |
| 培训 API | http://localhost:8000/health |

**回归：** 登录 → 资料列表/版本对比 → 项目管理 → 排班 → 资质查询 → 权限边界。

## 7. 单次任务流程

```
1. 读 README_FOR_CODEX + PROJECT_STATUS
2. 读相关 docs/modules/ 文档
3. 对照 DEVELOPMENT 阶段，最小 diff 改代码
4. migration 扩展 DB
5. docker compose up --build 验证
6. 更新 docs/modules/ + docs/tasks/ + PROJECT_STATUS
7. 三仓库分别 commit
```

---

## 8. 文档同步义务

| 变更类型 | 更新 |
|----------|------|
| 新模块上线 | `PROJECT_STATUS.md` + 对应 `docs/modules/` |
| 新表/字段 | `docs/数据模型.md` + `docs/代码地图.md` |
| 架构决策 | `docs/系统总览.md` 或 `docs/tasks/` |
| 小 bugfix | 可不扩架构文档 |

## 9. 极空间同步

- NAS 常无 git → 拷贝变更目录 + `docker compose build`
- **勿覆盖** `data/`、`uploads/`
- 前端 UI 旧：重建 frontend 容器且 `--no-cache`

详见 [modules/整合与部署.md](./modules/整合与部署.md)。
