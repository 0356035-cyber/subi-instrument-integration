## 1. 仓库职责

| 需求类型 | 仓库 | 目录倾向 |
|----------|------|----------|
| 项目 / 资料 / 数据集 / 分析 / 报告 / AI / 权限 | `subi_knowledge_platform` | `backend/<域>/`、`frontend/*_pages.py` |
| 培训 / 考核 / 授权 / 资质 API | `instrument-training-home` | `app/`、`streamlit_app/` |
| Compose / 备份 / 部署脚本 | 整合仓 `C:\projects` | 根目录 |

**禁止：** 在 `frontend/app.py` 或 `backend/main.py` 继续追加大型新域逻辑。新模块应优先拆到 `backend/<域>/`、`frontend/*_pages.py`，主入口只保留注册、导航与薄协调逻辑。

## 2. 目录与命名

### Sub-I 后端

- 入口：`backend/main.py`（逐步 `include_router` 拆分）
- 稳定域：`schedule_*.py`、`document_*.py`、`integrations/`
- 权限：`permissions.py`、`permission_migrations.py`、`role_seed.py`
- 新域规划：`backend/datasets/`、`analysis/`、`reports/`、`worklogs/`、`ai_workspace/`

### Sub-I 前端

- 主壳：`frontend/app.py`
- 按域拆分：`project_management.py`、`schedule_*.py`、`qualification_inquiry.py`
- 规划：`dataset_pages.py`、`analysis_pages.py`、`report_pages.py`、`worklog_pages.py`、`ai_workspace.py`

### 数据库迁移

- 项目相关：`project_migrations.py`
- 排班相关：`schedule_migrations.py`
- 权限相关：`permission_migrations.py`
- 新模块：各域 `migrations.py`

#### 迁移发布规则

- 培训系统使用 Alembic：每次表结构变更须新增 revision，在隔离 SQLite 库验证升级到 `head`，不手改数据库文件。
- Sub-I 使用域内幂等 `ensure_*` 迁移：变更须同时覆盖空库与已有表场景；启动期迁移只允许增量、可重复、非破坏性的 DDL。
- 涉及历史状态、JSON 结果或附件路径时，优先兼容读取，不在启动时批量改写业务数据；任何数据修复另立任务、先备份、再确认。
- 发布顺序固定为：确认备份可用 → 执行隔离验证 → 构建/启动 → 检查健康接口和受影响路径。恢复只允许使用明确确认的备份目录，且恢复演练必须指向隔离代码副本。

## 3. 硬约束（不可违反）

1. 不合并 `instrument-training-home` 进 Sub-I
2. Sub-I 前端只调 8001；培训 JWT 仅存 `.env`
3. 不删除稳定能力除非文档明确废弃
4. 统计最终结论经规则引擎 + 人审
5. `*.db`、`uploads/` **不提交 Git**
6. `role` ≠ `job_title`；项目负责人靠 `owner_employee_id`
7. 极空间保持 `docker compose` 一键四容器

## 4. 依赖与环境

### Sub-I 环境变量（`subi_knowledge_platform/.env`）

```env
INSTRUMENT_TRAINING_API_BASE=http://localhost:8000/api/v1
INSTRUMENT_TRAINING_SERVICE_EMPLOYEE_ID=3267
INSTRUMENT_TRAINING_SERVICE_PASSWORD=<强密码>
INSTRUMENT_TRAINING_TIMEOUT=10
```

### 培训系统环境变量（`instrument-training-home/.env`）

生产部署从 `instrument-training-home/.env.example` 建立本地 `.env`，不得提交、打印或复制其中密钥。Docker Compose 在运行时注入该文件，且 Docker 构建上下文会排除它。

```env
APP_ENVIRONMENT=production
JWT_SECRET=<至少32位随机密钥>
CORS_ALLOWED_ORIGINS=http://127.0.0.1:8501,http://localhost:8501
BOOTSTRAP_ADMIN_PASSWORD=<至少12位首次管理员密码>
```

生产环境禁止 JWT 弱默认值和 `CORS_ALLOWED_ORIGINS=*`；配置不合规时应拒绝启动。

### 依赖安装

```bash
cd subi_knowledge_platform/backend && pip install -r requirements.txt
cd ../frontend && pip install -r requirements.txt
```

## 5. 运行方式

### 只读健康检查（接管优先）

每次 Codex 接管项目时，先按 [只读健康检查.md](./只读健康检查.md) 做不启动、不写入的现场确认。该流程只允许读取非敏感文档、列目录、检查关键路径是否存在、查看 Git 状态。

只读检查不得升级为以下操作：启动 Docker、启动服务、构建镜像、运行 pytest、运行冒烟脚本、执行备份/恢复、修改 `.env`、处理 Git `safe.directory`。

### 推荐：Docker 四容器

```bat
C:\projects\启动系统.bat
```

或 `start-docker.bat`。

### 本地 Python（调试用）

```bat
subi_knowledge_platform\启动资料库系统.bat
```

先启后端（8001），再启前端（8510）；资质查询需培训 API（8000）。

### 验证清单

| 检查项 | 地址 |
|--------|------|
| Sub-I 前端 | http://localhost:8510 |
| Sub-I API | http://localhost:8001/health |
| 培训前端 | http://localhost:8501 |
| 培训 API | http://localhost:8000/health |

**回归：** 登录 → 资料列表/版本对比 → 项目管理 → 排班 → 资质查询 → 权限边界。

## 6. 测试

| 层级 | 要求 |
|------|------|
| 单元测试 | 新统计规则、新 CRUD 应有 |
| API | 延续现有 pytest 风格 |
| UI | Streamlit 关键路径手测 |
| 回归 | 资质查询、版本对比、登录白名单不回归 |

培训系统测试示例：`tests/test_record_id_resequence.py`

培训系统的隔离测试依赖见 `instrument-training-home/requirements-dev.txt`；该清单在运行依赖之外增加 `pytest`，仅用于开发或 CI，不用于常规运行镜像。

### 命令风险边界

完整命令分级见 [只读健康检查.md](./只读健康检查.md)。摘要：

| 类型 | 允许程度 | 示例 |
|------|----------|------|
| 安全只读 | 接管检查可用 | `Test-Path <path>`、`Get-ChildItem -Force`、读取非敏感 `.md`、`git status --short` |
| 谨慎只读 | 可记录现象，不自动修复 | 子仓 `git status` 触发 `dubious ownership`、阅读 `docker-compose.yml` 服务结构 |
| 未确认禁止 | 不属于只读检查 | `docker compose up`、`pytest`、冒烟脚本、备份/恢复脚本、`git config --global --add safe.directory` |

真实 `.env` 只检查是否存在，不打印、不复制、不解析内容。`data/`、`uploads/`、`backups/` 只检查目录是否存在，不枚举敏感文件细节。

### 测试风险分类

| 类型 | 示例 | 数据影响 | 运行要求 |
|------|------|----------|----------|
| 纯内存测试 | `instrument-training-home/tests/test_record_id_resequence.py`、`test_excel_import_service.py`、`test_login_permission.py` 等使用 `sqlite:///:memory:` 的测试 | 不写真实数据库 | 可在确认依赖可用后运行 |
| 真实 API 测试 | `instrument-training-home/tests/test_training_api.py`、`test_assessment_api.py`、`test_authorization_api.py` 等请求 `127.0.0.1` 端口的测试 | 会调用正在运行的服务，可能创建/删除测试记录 | 运行前必须确认目标服务、端口和测试数据库隔离情况 |
| 写库冒烟脚本 | `subi_knowledge_platform/backend/scripts/dataset_smoke_test.py`、`analysis_smoke_test.py`、`permission_ops_validation.py` | 会通过 API 写入 Sub-I 数据库，可能留下 `[Dataset冒烟]`、`[Analysis冒烟]` 或权限验证数据 | 运行前必须确认 `SUBI_DATA_PROFILE`、用户授权和测试账号密码 |

运行写库脚本前必须做到：

1. 明确说明脚本会写入哪些系统和数据类型。
2. 确认 `SUBI_DATA_PROFILE`；`production` 下默认不得写库。
3. 获取用户明确授权。
4. 使用环境变量传入当前测试密码，不在脚本或文档中写真实密码。
5. 运行后记录产生的样例数据和清理建议。

## 11. 数据安全红线

业务数据（`*.db`、`uploads/`）与代码**完全分离**：

| 规则 | 说明 |
|------|------|
| 不进 Git | `data/subi_knowledge.db` 等**不得**被 `git add`；已跟踪的须 `git rm --cached` |
| 禁止 git 还原库 | **切勿** `git checkout -- data/subi_knowledge.db`（会用旧快照覆盖现网） |
| 备份 | 手动 `backup-data.bat`；极空间/生产机安装 `install-scheduled-backup.bat` |
| 恢复 | `restore-data.bat` 须输入备份文件夹名；自动写 `pre_restore_*` 安全副本 |
| 开发 / 正式 | 本地默认 `SUBI_DATA_PROFILE=dev`；极空间 compose 覆盖为 `production` |
| 测试脚本 | `permission_ops_validation.py` 等写入数据的脚本，在 `production` 下**默认拒绝** |
| 提交前钩子 | 运行 `setup-git-hooks.bat` 安装 pre-commit，阻止误提交 db/uploads |

校验：`verify-data-safety.bat`（检查 Git 跟踪、备份完整性、现库 PRAGMA）。
