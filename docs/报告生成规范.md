# 报告生成规范

> **用途：** Word/PDF/Excel 报告生成、模板、排版与结果呈现规则。  
> **何时读：** 开发或审查 Report 模块（阶段 6）时。  
> **状态：** 阶段 6 的 6A 报告工作台已实现；docx 生成和归档仍属后续阶段。实现见 [modules/报告生成.md](./modules/报告生成.md)。
> **关联：** 分析结果见 [数据分析规范.md](./数据分析规范.md)；数据模型见 [数据模型.md](./数据模型.md)。

**更新日期：** 2026-08-12

---

## 1. 基本原则

```
模块来源确认 → Word 模板填充 → 结果表/图插入 → Results 文本（可先人工，后 AI 辅助润色）→ 人工审核 → 定稿归档
```

- **不由 AI 自由排版**
- **复杂 CSR 不全自动**
- 定稿须回挂为项目 Document

---

## 2. 模板管理

| 项 | 约定 |
|----|------|
| 目录 | `subi_knowledge_platform/templates/word/` |
| 版本 | 模板文件纳入 Git；生成实例不入库 |
| 类型 | 统计报告、CSR 摘要等（见 `report_type` 枚举） |

在模板填充能力实施前，报告制作人先在项目「报告」Tab 的工作台中选择来源。首个工作台模板为通用人体功效评价报告，固定模块与来源约束见 [modules/报告生成.md](./modules/报告生成.md)。

试验目的模块采用确定性规则生成草稿：从项目测试环节识别临床评估、无创性仪器检测和自我评估问卷调查；从项目名称识别单次使用与连续周数；从 `trial_samples` 取试验样品，并从 `claim_type` 按原顺序取前三项功效宣称。缺失信息仍写入正文，但使用 `【待补充：…】` 标记突出，并在界面逐项说明补充入口。草稿必须由报告制作人核对并可手工修改，不能作为自动定稿内容。

受试者与筛选标准模块必须选择项目 CRF 中的筛选表作为来源。系统默认写入“至少30例试验参与者最终完成全部试验”；当 CRF 明确给出例数时，以识别到的数值替代默认值。入选标准、排除标准按 CRF 可检索正文的原始编号和顺序逐条提取，不改写或合并条目；同时兼容常见的“编号列 + 条目列”筛选表格式。选择 CRF 后立即预览自动草稿；当仅有一份候选 CRF 时默认预览该资料。作者可逐条核对、编辑并确认。未识别的入排标准仍使用 `【待补充：…】` 标记，并提示到项目资料补充或更换 CRF。

## 3. 生成流程（第一版）

1. 创建报告并选择模板类型
2. 按报告模块选择 Project Document 和已通过审核的 AnalysisTask，或填写人工内容
3. 对不良事件和方案偏离明确确认“未发生”，不能以空白替代确认
4. 填充占位符（项目信息、表格数据）
5. 插入结果表（来自已选择任务的 `result_json`）
6. Results 章节：人工撰写为主，AI 仅辅助润色
7. 导出 docx → 人工审核 → 上传为 Document（`document_type=Statistical Report` 等）

---

## 4. 报告类型（`report_type`）

- `Statistical Report` — 统计分析报告
- `Clinical Study Report` — 临床研究报告（远期）
- `Summary Report` — 摘要报告
- `Ethics Submission Document` — 伦理递交文件

---

## 5. 状态与审核

| 状态 | 含义 |
|------|------|
| 草稿 | 可重新生成 |
| 待审 | 已生成，等待负责人/主任审核 |
| 定稿 | 不可自动覆盖；新版本升 `version` |

`reviewed_by` 记录审核人；`generation_log_json` 记录填充过程。

---

## 6. 本阶段不做

- AI 全权排版与签发
- 复杂 CSR 全自动生成
- PDF 作为唯一编辑格式（docx 为主）

---

## 7. 验收标准

一份统计报告 docx 从模板生成，审核后挂回项目，权限与版本规则正确。
