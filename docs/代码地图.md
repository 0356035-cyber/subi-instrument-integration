中文脚本用于日常双击；英文脚本和 `scripts/` 下文件承载主要逻辑。

| 日常入口 | 实际逻辑入口 | 风险 |
|----------|--------------|------|
| `启动系统.bat` | `start-docker.bat` → `scripts/start-docker.ps1` | 启动/构建，中风险 |
| `启动系统-极空间.bat` | `start-docker-zspace.bat` → `scripts/start-docker.ps1 -Mode zspace` | 启动/构建，中风险 |

### 1.3 系统边界

- `instrument-training-home` 保持独立，负责人员、仪器、培训、考核、授权和资质整合 API。
- `subi_knowledge_platform` 负责项目、资料、排班、Dataset、Analysis、Report 规划和资质 BFF。
- Sub-I 前端只调用 Sub-I 后端 `:8001`。
- Sub-I 后端通过 `/integrations/training/*` 调用培训 API `:8000/api/v1`。
- 不直接复制培训全表到 Sub-I，不直接写培训库，不把培训系统并入 Sub-I。

## 7. 仪器培训系统（摘要）

详见 [modules/仪器培训系统.md](./modules/仪器培训系统.md)。仪器主数据与维护校准记录均在该子系统保存；Sub-I 后续只经 BFF 查询和关联仪器 ID。

培训记录的管理端页面为 `instrument-training-home/streamlit_app/03_training_management.py`，后端路由为 `instrument-training-home/app/api/v1/training_records.py`，业务校验与写入在 `instrument-training-home/app/services/training_record_service.py`。历史科目培训转换使用 `POST /api/v1/training-records/batch-convert-to-instrument`：仅管理者可用，前端须明确选择记录和目标仪器；后端保证同科目、同日期、同讲师的全量校验后才原子转换，不会自动补建考核或授权。

考核记录的管理端页面为 `instrument-training-home/streamlit_app/04_assessment_management.py`，后端路由为 `instrument-training-home/app/api/v1/assessment_records.py`，业务校验与写入在 `instrument-training-home/app/services/assessment_record_service.py`。历史科目考核转换使用 `POST /api/v1/assessment-records/batch-convert-to-instrument`：仅管理者可用，需明确选择同科目、同考核日期、同考核人的记录及目标仪器；后端整批校验后原子转换，保留每人的成绩与结果，不自动创建培训或授权。

培训系统人员模型位于 `instrument-training-home/app/models/user.py`，人员管理页面为 `streamlit_app/01_personnel_management.py`。`personnel_type` 区分本科室人员和外部人员，`employment_status` 记录在岗、退休、离职；退休和离职人员保留历史记录，但服务层拒绝新建培训、考核、授权。只有本科室在岗且有工号的人员进入 Sub-I 同步与资质整合接口。

整合 API 前缀：`/api/v1/integrations/*`（:8000）

历史培训考核分类导入：`instrument-training-home/app/services/historical_import_service.py` 负责解析审核后的分类工作簿、创建历史人员与通用科目、写入培训/考核记录及批次审计；`app/api/v1/imports.py` 提供 `POST /imports/historical-classified`；前端入口为 `streamlit_app/08_data_import.py` 的「历史培训考核」页签。该路径不创建仪器或授权。

历史编号回填：`app/services/historical_number_backfill_service.py` 只读取两份原始年度 Excel 并匹配既有空编号记录；`POST /imports/historical-number-backfill` 支持预览与受控提交，前端位于 `08_data_import.py` 的「历史编号回填」页签。该路径不创建培训、考核、人员或科目，正式提交只更新空的原始编号字段并记录导入批次与操作日志。

培训系统角色边界：`instrument-training-home/app/core/permissions.py`；培训、考核记录写 API 使用 `RecordEditorOrTrainerOrAdmin`，授权写 API 仅使用 `AdminUser`。前端导航与操作按钮边界由 `streamlit_app/auth_session.py` 控制。

培训/考核查询：`app/api/v1/training_records.py`、`app/api/v1/assessment_records.py` 负责关键词、日期范围、对象类型、部门、科目分类及考核结果的受权限保护筛选；查询实现位于对应 `app/services/*_record_service.py`。前端记录管理筛选位于 `streamlit_app/03_training_management.py` 和 `04_assessment_management.py`；统一年度时间线与三工作表导出位于 `07_statistics_report.py`、`date_filter.py`、`export_utils.py`。

培训/考核场次查询：`streamlit_app/record_event_grouping.py` 以只读方式将个人记录聚合为培训或考核场次，并保留参与人员明细；`07_statistics_report.py` 提供场次选择、年度汇总和导出。`TrainingRecord.original_training_number` 与 `AssessmentRecord.original_assessment_number` 保存原始 Excel 的 `年度-序号`，例如 `2025-07`；系统 `id` 仅作为内部记录号。历史培训优先使用原始编号或已写入培训内容的导入事件 ID；未回填编号的历史考核按日期、对象、考核人近似聚合，具体限制见 `docs/modules/仪器培训系统.md`。
