## 最终结论（仍有效部分）

### 架构

- **不另建子库**，一个 Sub-I 总库，用 `project_id`、角色、成员关系区分
- **不建完整 LIMS**；样品流、仪器直采仍用专业工具
- **不合并培训系统**；资质经 BFF 联邦查询

### 外用分工

| 能力 | 归属 |
|------|------|
| 项目运营、资料、排班、审计 | 本系统 |
| Word 定稿 | Microsoft Word |
| 复杂统计 | SPSS / GraphPad / R |
| 培训台账 | instrument-training-home |

### 排班（§14.11）

- 访视节点 + 项目日历 + 周排班已落地
- **明确不做：** 复制上周排班、拖拽甘特图

### 权限（§14.12）

- 详见 [modules/权限与用户管理.md](../modules/权限与用户管理.md)（现行完整版）
- MVP 已于 2026-07-06 上线

## 废弃方案及原因

| 方案 | 原因 |
|------|------|
| 每人一套独立子库 | 人员调动成本高；已改为总库 + 项目关系 |
| 标题完全一致版本归组 | 已改为 `document_group_id` |
| 复制上周排班 | 团队确认不需要 |
| 立即整体重写为 2.0 | 改为渐进演进，四容器不变 |

## 迭代机制（§14.8，仍建议遵循）

每完成一个真实项目回顾约 15 分钟，更新 `PROJECT_STATUS.md` 与相关 `docs/tasks/`。
