## 0. 项目概况

本项目是一个基于 **Streamlit + FastAPI + SQLite** 的本地部署资料管理平台，用于临床研究 Sub-I 团队内部管理法规指南、伦理资料、模板文件、培训课件和部门内部要求等资料。

前端主文件：



- 上传资料

## 2. 版本管理核心逻辑

当前系统围绕“同标题资料视为同一份资料的不同版本”建立版本管理逻辑。

### 2.1 版本归组规则

当前规则：

```text
title 完全一致 = 同一份资料的不同版本
```

示例：

```text
GCP指南
GCP 指南
GCP指南 V2.0
```

以上会被认为是三份不同资料。

因此系统使用时要注意：

- 上传新版本时标题不可编辑；
- 标题应保持完全一致；
- 版本号应放在 `version` 字段，而不是写进标题里。

---

### 2.2 生效日期解析函数

对应函数：

```python
parse_effective_date(date_str)
```

用途：

- 将生效日期转换为 `datetime`；
- 支持格式：

```text
2026-01-01
2026/01/01
```

- 无法解析时返回：

```python
datetime.min
```

当前函数：

```python
def parse_effective_date(date_str):
    if not date_str:
        return datetime.min

    date_str = str(date_str).strip()

    for fmt in ["%Y-%m-%d", "%Y/%m/%d"]:
        try:
            return datetime.strptime(date_str, fmt)
        except ValueError:
            continue

    return datetime.min
```

---

### 2.3 合并同标题资料，只保留最新版

对应函数：

```python
get_latest_documents_by_title(documents)
```

用途：

- 将同标题的多个版本合并成一条；
- 每个标题只保留最新版。

判断规则：

```text
effective_date 最晚 = 最新版
effective_date 相同，则 id 更大 = 最新版
```

已用于：

- 首页 `show_dashboard()`
- 资料列表 `show_document_list()`

---

### 2.4 获取同标题全部版本

对应函数：

```python
get_versions_by_title(title)
```

用途：

- 在资料详情页显示版本时间线；
- 获取同标题下所有版本；
- 按生效日期倒序排列；
- 生效日期相同时按 id 倒序。

当前已经解决过报错：

```text
NameError: name 'get_versions_by_title' is not defined
```

该函数目前已经存在并可用。

---

### 2.5 自动刷新版本状态

对应函数：

```python
refresh_version_status_by_effective_date(title)
```

用途：

根据同标题下所有版本的生效日期自动刷新状态：

```text
生效日期最晚的版本 = 现行
其他版本 = 废止
```

重要修复：

之前函数内部 PUT 调用错误使用：

```python
data=update_data
```

已改为：

```python
json=update_data
```

原因是当前 `api_request()` 中 PUT 请求写法为：

```python
elif method == "PUT":
    resp = requests.put(url, headers=headers, json=json, timeout=10)
```

## 3. 上传资料与上传新版本

### 3.1 上传新资料

对应函数：


当前逻辑：

- 支持选择分类、状态、版本、生效日期、标签、摘要；

```python

```

因此如果上传的是同标题资料，系统会重新判断哪个版本是现行。

上传成功后的逻辑示例：

```python
result, err = api_request("POST", "/documents", data=form_data, files=files)

if err:
    st.error(f"上传失败：{err}")
else:
    refresh_ok, refresh_msg = refresh_version_status_by_effective_date(title)

    if refresh_ok:
        st.success(f"资料「{title}」上传成功。{refresh_msg}")
    else:
        st.warning(f"资料「{title}」上传成功，但版本状态刷新失败：{refresh_msg}")

    st.balloons()
```

### 11.2 优先级 2：优化上传新版本入口

### 11.3 优先级 3：新增独立资料详情页

如果以后还想实现“首页点击资料直接进入详情”，不建议再在 HTML 卡片里硬塞链接。

推荐新增页面状态：

```python
current_page = "资料详情"
```

新增函数：

```python
def show_single_document_page():
    doc_id = st.session_state.selected_doc_id

    if not doc_id:
        st.warning("未选择资料。")
        return

    if st.button("← 返回上一页"):
        st.session_state.current_page = "仪表盘"
        st.session_state.selected_doc_id = None
        st.rerun()

    show_document_detail(doc_id)
```

以后首页、分类详情、资料列表都可以统一跳转到这个详情页。

### 11.4 优先级 4：引入真正的版本组字段

当前版本归组依赖：

```text
title 完全一致
```

短期可用，但长期不稳。

后续更合理的数据结构是：

```text
document_group_id
```

每份资料一个固定 group id，同一资料的所有版本共享这个 id。

这样即使标题轻微修改，也不会破坏版本时间线。

## 12. 当前最重要的设计原则

后续修改时建议坚持以下原则：

### 12.1 所有资料列表展示都先按标题合并版本



### 12.3 状态字段是展示结果，不是判断依据

```text

```

### 12.4 历史版本不要出现在普通资料列表中

历史版本只在详情页时间线或版本模块中展示。

---

### 12.5 首页保持简单

当前首页只负责：

```text

```

---

### 12.6 复杂跳转不要用 HTML 链接

Streamlit 中 HTML 链接容易造成 session 丢失。

复杂导航应使用：

```python

```

- Sub-I 侧边栏「项目检测人员授权资质查询」**已接入**，不再为预留入口
- 新增 `frontend/qualification_inquiry.py` 资质查询页（按工号 / 按仪器、批量核验、仪器下拉、Excel 导出）
