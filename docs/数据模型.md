# 数据模型

> **用途：** 核心对象、字段与表关系；新功能设计时对照。  
> **何时读：** 加表/加列、写 API 或 migration 前。  
> **关联：** 落点见 [代码地图.md](./代码地图.md)；权限规则见 [modules/权限与用户管理.md](./modules/权限与用户管理.md)。

**更新日期：** 2026-07-06  
**策略：** 扩展优于重建；`project_id IS NULL` 仍为通用资料库。

---

## 1. 模型总览

```
Project（根）
├── Document[]              project_id 可空
├── ProjectMember[]         成员关系
├── Schedule 域             访视/日历/排班表
├── Dataset[]               【阶段 4】
├── AnalysisTask[]          【阶段 5】
├── Report[]                【阶段 6】
├── AIWorkspace             【阶段 7】
└── StaffQualification      视图（数据在培训系统）
```

---

## 2. User — 用户

| 字段 | 说明 |
|------|------|
| `employee_id` | 工号，登录唯一键 |
| `full_name` | 姓名 |
| `role` | 系统角色：`admin` / `schedule_manager` / `system_maintainer` / `editor` / `viewer` |
| `job_title` | 业务职务（**不驱动权限**） |
| `department` / `phone` | 科室、电话 |
| `is_active` / `must_change_password` | 启用、强制改密 |

---

## 3. Project — 项目

| 字段 | 说明 |
|------|------|
| `project_code` | 项目编号 |
| `name` | 项目名称 |
| `sponsor` | 申办方 |
| `claim_type` / `ethics_type` | 功效宣称（逗号分隔的多选值）、伦理类型 |
| `tags` | 标签 |
| `status` / `report_progress` | 项目状态；人工维护的报告进展（未启动 / 已完成草稿 / 已发申办方审核 / 已完成正式报告）。不替代阶段 6 的 Report 实体与归档记录。 |
| `summary` | 摘要 |
| `owner_employee_id` | **项目负责人工号** |
| `baseline_date` | 基线日 |
| `created_by` | 创建人工号 |

---

## 4. ProjectMember — 项目成员

| 字段 | 说明 |
|------|------|
| `project_id` | FK Project |
| `employee_id` | 成员工号 |
| `added_by` | 添加人 |

成员对项目资料/排期**只读**；负责人可编辑。

---

## 5. Document — 资料

| 字段 | 说明 |
|------|------|
| `project_id` | 可空；空 = 通用库 |
| `document_group_id` | 版本组 |
| `title` / `category` / `version` | 标题、分类、版本号 |
| `document_type` | Protocol / SAP / CRF / Raw Data / Statistical Report 等 |
| `audience_scope` | `all_staff` / `project_leads_only`（部门内部要求） |
| `effective_date` / `status` | 生效日、现行/废止 |
| `content_text` / `file_path` | 全文、附件路径 |

### 通用库可见性（由 `permissions.py` 实现）

| 分类 | 可见范围 |
|------|----------|
| 法规与指南、伦理审查、培训课件 | 全员 |
| 模板下载中心 | 项目负责人及以上 |
| 部门内部要求 | 由 `audience_scope` 决定 |

## 6. AuditLog / ProjectLeadNotification

**AuditLog：** 主任/管理员修改他人项目时写入。

| 字段 | 说明 |
|------|------|
| `actor_employee_id` / `actor_role` | 操作人 |
| `project_id` / `entity_type` / `entity_id` | 目标 |
| `action` / `summary` | 动作与摘要 |

**ProjectLeadNotification：** 负责人未读提醒，关联 `audit_id`，`read_at` 标记已读。

---

## 7. OnlinePresence（当前访问人数）

`online_presence` 记录浏览器会话的 `employee_id`、随机 `session_id` 与 `last_seen_at`。页面每分钟发送心跳；系统以近 5 分钟内的不同工号数作为当前访问人数。该表仅用于短期在线统计，不保存访问历史；仅 `admin` / `schedule_manager` 可查看汇总人数。

## 13. Analysis V2 第一阶段增量字段

`analysis_tasks` 保持为 Analysis 的最小可执行单元；V2 不新增独立的设计、结果、产物或审核实体。

| 字段 | 说明 |
|------|------|
| `analysis_version` | 递增执行版本；首次成功执行为 1 |
| `executed_by` / `executed_at` | 当前版本的执行人和执行时间 |
| `execution_history_json` | 重跑前保存的结果、日志和审核快照 |
| `review_status` | 未提交 / 待审核 / 已通过 / 已驳回 |
| `reviewed_by` / `reviewed_at` / `review_comment` | 人工审核留痕；驳回必须有意见 |

执行状态仍使用既有 `status`（草稿、已执行）。项目负责人可提交审核；`admin` 和 `schedule_manager` 可审核。审核权限基于 `role`，不使用 `job_title`。
