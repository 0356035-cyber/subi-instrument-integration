# 只读健康检查

> **用途：** Codex 每次接管本项目时，先用只读方式判断项目结构、文档入口、数据保护边界和 Git 状态是否正常。  
> **边界：** 本流程只读文件、列目录、查看 Git 状态；不启动服务、不构建镜像、不运行测试、不写数据库、不修改配置。

---

## 1. 总原则

只读健康检查用于“先确认现场”，不是验证业务功能。检查过程中不得为了求快升级为启动、构建、测试、备份、恢复或配置修复。

必须遵守：

1. 不运行 Docker / Compose。
2. 不启动 FastAPI、Streamlit 或任何本地服务。
3. 不运行 pytest、冒烟脚本、迁移脚本、备份脚本或恢复脚本。
4. 不读取、打印、复制或解析 `.env`、`.env.tunnel`、`subi_knowledge_platform/.env` 的真实内容。
5. 只检查 `data/`、`uploads/`、`backups/` 目录是否存在，不枚举敏感文件细节，不读取内容。
6. 子仓 Git 如出现 `dubious ownership` / `safe.directory`，只记录现象，不自动处理。
7. `docker-compose.yml` 只允许确认存在和阅读服务结构，不允许运行 compose 命令启动或构建。

---

## 2. 建议检查顺序

### 2.1 根目录与入口文档

确认当前目录是 `C:\projects`，并检查关键入口是否存在：

```powershell
Get-ChildItem -Force
Test-Path AGENTS.md
Test-Path README_FOR_CODEX.md
Test-Path PROJECT_STATUS.md
Test-Path docker-compose.yml
Test-Path docs
```

预期：

- `AGENTS.md` 存在。
- `README_FOR_CODEX.md` 存在。
- `PROJECT_STATUS.md` 存在。
- `docker-compose.yml` 存在。
- `docs/` 存在。

### 2.2 当前有效文档

只确认当前有效文档是否存在，不默认归档文档代表当前状态：

```powershell
Test-Path docs\系统总览.md
Test-Path docs\开发规范.md
Test-Path docs\代码地图.md
Test-Path docs\数据模型.md
Test-Path docs\modules
Test-Path docs\tasks
Test-Path docs\archive
Test-Path docs\只读健康检查.md
```

阅读优先级：

1. `AGENTS.md`
2. `README_FOR_CODEX.md`
3. `PROJECT_STATUS.md`
4. `docs/只读健康检查.md`
5. 与任务相关的 `docs/modules/`、`docs/tasks/`

### 2.3 子系统目录

确认两个子系统目录存在即可：

```powershell
Test-Path subi_knowledge_platform
Test-Path instrument-training-home
Test-Path subi_knowledge_platform\backend
Test-Path subi_knowledge_platform\frontend
Test-Path instrument-training-home\app
Test-Path instrument-training-home\streamlit_app
```

### 2.4 数据保护边界

只确认目录是否存在，不枚举文件、不读取数据库、不读取附件内容：

```powershell
Test-Path subi_knowledge_platform\data
Test-Path subi_knowledge_platform\uploads
Test-Path instrument-training-home\data
Test-Path backups
```

`.env` 只检查是否存在，不打印内容：

```powershell
Test-Path .env.example
Test-Path .env.tunnel.example
Test-Path subi_knowledge_platform\.env.example
Test-Path subi_knowledge_platform\.env
Test-Path .env.tunnel
```

说明：

- `.env` 或 `.env.tunnel` 不存在不一定是错误，可能表示尚未配置本机或 Tunnel。
- 不得运行 `Get-Content .env`、`type .env` 或任何会输出真实密钥的命令。

### 2.5 Git 状态

根仓可做只读状态检查：

```powershell
git status --short
```

子仓状态检查可能触发 `dubious ownership`，只记录现象：

```powershell
git -C subi_knowledge_platform status --short
git -C instrument-training-home status --short
```

若出现 `safe.directory` 提示，不要自动运行 `git config --global --add safe.directory ...`。应在报告中写明：“子仓 Git 状态因 dubious ownership 无法读取，需用户确认后处理。”

### 2.6 Compose 文件只读检查

可以打开 `docker-compose.yml` 阅读服务结构：

```powershell
Get-Content -Encoding UTF8 docker-compose.yml
```

禁止在未确认前运行：

```powershell
docker compose up
docker compose up -d
docker compose up -d --build
docker compose down
docker compose build
```

## 3. 命令分级

### 3.1 安全只读命令

这些命令只查看文件或状态，通常可用于接管检查：

```powershell
Get-ChildItem -Force
Test-Path <path>
Get-Content -Encoding UTF8 <非敏感文档>
git status --short
rg --files -g "!data/**" -g "!uploads/**" -g "!backups/**" -g "!.env" -g "!.env.tunnel"
```

注意：`Get-Content` 只用于非敏感文档，例如 `.md`、`.gitignore`、`docker-compose.yml`。不得用于真实 `.env`。

### 3.2 需要谨慎的只读命令

这些命令理论上只读，但可能输出敏感路径、过多文件、或触发环境权限提示：

| 命令 | 谨慎原因 | 规则 |
|------|----------|------|
| `Get-ChildItem data/uploads/backups -Recurse` | 可能枚举业务数据、附件或备份细节 | 不用于默认健康检查 |
| `git -C <子仓> status --short` | 可能触发 `dubious ownership` | 只记录，不自动处理 |
| `Get-Content docker-compose.yml` | 只读安全，但可能让人误接着运行 compose | 只阅读结构，不运行 compose |
| `rg --files` | 可能枚举敏感目录 | 必须排除 `data/`、`uploads/`、`backups/` 和真实 `.env` |

### 3.3 未确认前禁止运行的命令

这些命令会启动、构建、测试、写数据、改配置或覆盖数据，不能作为只读健康检查的一部分：

```powershell
docker compose up
docker compose up -d
docker compose up -d --build
docker compose down
docker compose build
pytest
python subi_knowledge_platform\backend\scripts\dataset_smoke_test.py
python subi_knowledge_platform\backend\scripts\analysis_smoke_test.py
python subi_knowledge_platform\backend\scripts\permission_ops_validation.py
backup-data.bat
restore-data.bat
启动系统.bat
start-docker.bat
git config --global --add safe.directory <path>
```

## 4. 健康检查输出建议

只读检查完成后，建议报告：

1. 根目录是否是预期工作区。
2. 关键入口文档是否存在。
3. `docs/` 当前有效文档是否完整。
4. 两个子系统目录是否存在。
5. 数据目录、附件目录、备份目录是否存在；不列出敏感文件细节。
6. `.env.example` 是否存在；真实 `.env` 是否存在但不打印内容。
7. 根仓 Git 状态摘要。
8. 子仓 Git 是否可读；如遇 `dubious ownership`，只记录现象。
9. 是否发现高风险操作需求；若有，等待用户确认。

---

## 5. 异常处理

| 现象 | 处理 |
|------|------|
| 缺少 `AGENTS.md` | 建议创建或恢复，不直接生成除非用户确认 |
| 缺少 `README_FOR_CODEX.md` / `PROJECT_STATUS.md` | 停止开发，先向用户确认文档来源 |
| 缺少 `subi_knowledge_platform/` 或 `instrument-training-home/` | 说明子仓缺失，不自动 clone |
| 缺少真实 `.env` | 只报告“不存在或未配置”，不自动创建 |
| 子仓 Git `dubious ownership` | 记录现象，不处理 `safe.directory` |
| `data/` / `uploads/` 缺失 | 只报告风险，不自动创建或恢复 |

---

## 6. 本轮不做

本流程不替代以下操作：

- 功能回归测试
- Docker 健康检查
- 数据库完整性校验
- 备份完整性校验
- 服务可用性验证
- 迁移验证

如用户需要上述检查，必须另行说明命令、目的、影响和风险，等待确认后再执行。
