## 2. 更新策略对比

| 方案 | 适用 | 说明 |
|------|------|------|
| **A. 离线包** | U 盘 / 文件管理器拷贝 | 运行 `导出离线部署包.bat`，整包拷到 NAS；适合无稳定 SSH |
| **B. Z 盘直拷** | Z 盘稳定挂载时 | 不推荐；挂载不可靠 |
| **C. SSH 传包（推荐）** | 开发机与 NAS 同局域网 | 本机 `build` + `tar` + `scp` 到 NAS `/tmp`，root 解压部署 |

下文以 **方案 C** 为主（2026-07-06 验证通过）。

## 3. 更新前检查

- [ ] 电脑与极空间在**同一局域网**
- [ ] 开发机 **Docker Desktop 已启动**，本地 `docker compose build` 成功

## 4. 阶段 A：开发机打包（PowerShell）

在 **Windows 终端** 执行（工作目录 `D:\projects`）：

```powershell
cd D:\projects

# --- 1) 拉取最新代码（三仓库）---
git pull
Push-Location instrument-training-home; git pull; Pop-Location
Push-Location subi_knowledge_platform; git pull; Pop-Location

# --- 2) 构建镜像 ---
docker compose build
if ($LASTEXITCODE -ne 0) { throw "build failed" }

# --- 3) 导出镜像 tar（自动读取 compose 镜像名）---
$images = @(docker compose config --images 2>$null | Where-Object { $_ -and $_.Trim() })
Write-Host "Images:"; $images | ForEach-Object { Write-Host "  $_" }
docker save -o D:\projects\docker-images-latest.tar @images
if ($LASTEXITCODE -ne 0) { throw "docker save failed" }

# --- 4) 打代码包（排除业务数据与密钥）---
# 在 projects 根目录打包，解压后目录结构不变
tar -czf D:\projects\projects-code.tar.gz `
  --exclude="./instrument-training-home/data" `
  --exclude="./subi_knowledge_platform/data" `
  --exclude="./subi_knowledge_platform/uploads" `
  --exclude="./subi_knowledge_platform/.env" `
  --exclude="./subi_knowledge_platform/.env.integration" `
  --exclude="./instrument-training-home/.env" `
  --exclude="./.git" `
  --exclude="./backups" `
  --exclude="./terminals" `
  -C D:\projects .

Get-Item D:\projects\projects-code.tar.gz, D:\projects\docker-images-latest.tar |
  Format-Table Name, @{N='MB';E={[math]::Round($_.Length/1MB,1)}}
```

> **说明：** 不要把手上的旧 `offline-deploy_*` 包当「最新版」——以本次 `git pull` + `build` 产物为准。  
> 若更习惯一键脚本，可用 `导出离线部署包.bat`（选 **跳过业务数据**），再把包内 `projects` 与 `docker-images.tar` 按下面步骤传到 NAS。

## 6. 阶段 C：极空间部署（root）

### 6.1 连接与提权

```powershell
ssh -p 10000 13816937329@192.168.50.56
```

```bash
sudo -i
```

### 6.2 变量（整段脚本会用到）

```bash
TARGET="/tmp/zfsv3/sata11/13816937329/data/docker/projects"
STAMP=$(date +%Y-%m-%d_%H%M%S)
BACKUP_DIR="/tmp/zfsv3/sata11/13816937329/data/docker/backups/pre_update_$STAMP"
```

### 6.3 备份业务数据（必做）

```bash
mkdir -p "$BACKUP_DIR"
cp -a "$TARGET/instrument-training-home/data/instrument_training.db" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/data/subi_knowledge.db" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/uploads" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/.env" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/.env.integration" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/instrument-training-home/.env" "$BACKUP_DIR/training.env" 2>/dev/null || true
ls -la "$BACKUP_DIR"
echo "Backup OK: $BACKUP_DIR"
```

在备份与解压前，三个运行时配置必须存在；缺少任一个即停止部署：

```bash
test -f "$TARGET/subi_knowledge_platform/.env" || { echo "missing Sub-I .env"; exit 1; }
test -f "$TARGET/subi_knowledge_platform/.env.integration" || { echo "missing BFF .env.integration"; exit 1; }
test -f "$TARGET/instrument-training-home/.env" || { echo "missing training .env"; exit 1; }
```

### 6.4 解压代码并加载镜像

```bash
cd "$TARGET"

# 解压代码（覆盖除 data/uploads/.env 外的文件；上述目录未打进包）
tar -xzf /tmp/projects-code.tar.gz -C "$TARGET"

# 加载镜像
docker load -i /tmp/docker-images-latest.tar
```

> 解压与 `docker load` 均需 **root**；普通用户会遇到 `docker.sock` 权限错误或解压失败。

### 6.5 端口：8001 冲突时改为 18001

极空间系统服务 `downloader` 可能占用宿主机 **8001**。Sub-I 后端对外映射需避开：

```bash
cd "$TARGET"
# 根目录 .env 仅供 Docker Compose 读取宿主机端口；不要改容器内部 8001。
if [ -f .env ] && grep -q '^SUBI_API_HOST_PORT=' .env; then
  sed -i 's/^SUBI_API_HOST_PORT=.*/SUBI_API_HOST_PORT=18001/' .env
else
  printf 'SUBI_API_HOST_PORT=18001\n' >> .env
fi
chmod 600 .env
```

- 用户仍通过 **8510** 访问 Sub-I 页面，**无需改浏览器地址**。
- `18001` 仅供宿主机调试 API，勿映射到公网。

### 6.6 启动容器

```bash
cd "$TARGET"
docker compose -f docker-compose.yml -f docker-compose.zspace.yml up -d --no-build

sleep 10
docker compose ps
```

`docker-compose.zspace.yml` 会设置 `SUBI_DATA_PROFILE=production`（生产只读保护）。

若已配置 Cloudflare Tunnel，业务容器起来后再启 Tunnel（见 [回家部署清单](./archive/回家部署清单-2026-06-26.md) §3）。

### 6.7 清理临时文件（可选）

```bash
rm -f /tmp/projects-code.tar.gz /tmp/docker-images-latest.tar
```

## 8. 风险与应对策略一览

> 2026-07 整合升级后，极空间部署从「四容器 + 3267 兼服务账号」变为「五容器 + 专用 BFF 账号 + 培训 `/ready` 就绪链」。下表供部署前速查。

### 8.0 风险等级说明

| 等级 | 含义 |
|------|------|
| **高** | 不处理则整栈或核心功能（资质/同步）不可用 |
| **中** | 可部分运行，但功能降级或需人工补救 |
| **低** | 影响面小，或有明确绕过方式 |

### 8.1 高风险：缺少 Compose 要求的配置文件

| 项目 | 说明 |
|------|------|
| **风险** | `docker compose up` 报 `env file ... not found`，容器无法创建 |
| **触发条件** | 缺少 `instrument-training-home/.env` 或 `subi_knowledge_platform/.env.integration` |
| **应对策略** | 在 NAS 从示例复制并填写，**更新前**确认三个文件均存在 |

```bash
TARGET="/tmp/zfsv3/sata11/13816937329/data/docker/projects"
cp "$TARGET/instrument-training-home/.env.example" "$TARGET/instrument-training-home/.env"
cp "$TARGET/subi_knowledge_platform/.env.integration.example" "$TARGET/subi_knowledge_platform/.env.integration"
# 再用 vi 填写实际密钥与密码；subi_knowledge_platform/.env 若已有则保留
```

### 8.2 高风险：培训生产配置校验失败 → 全栈连锁不启动

| 项目 | 说明 |
|------|------|
| **风险** | `instrument_train_backend` 启动失败 → 培训前端、Sub-I 后端均因 `depends_on: service_healthy` 不启动 |
| **触发条件** | `APP_ENVIRONMENT=production` 但 `JWT_SECRET` 不足 32 位、`CORS_ALLOWED_ORIGINS=*`、整合账号密码不足 12 位等 |
| **应对策略** | 保持 `APP_ENVIRONMENT=production`，一次性配齐强 JWT 密钥、明确 CORS 白名单和整合账号配置；不得以 `development` 绕过生产校验 |

**排查：**

```bash
docker compose logs instrument_train_backend --tail 80
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000/ready
```

期望 `/ready` 返回 `200`。

### 8.3 高风险：整合服务账号工号冲突或凭据不一致

| 项目 | 说明 |
|------|------|
| **风险** | 培训容器退出：`整合服务工号已被普通人员占用`；或 Sub-I 报 `TRAINING_AUTH_FAILED` |
| **触发条件** | `INTEGRATION_SERVICE_EMPLOYEE_ID=3267`（3267 已是真人账号）；或培训 `.env` 与 Sub-I `.env.integration` 密码不一致 |
| **应对策略** | **禁止**用 3267 作服务账号；使用专用工号（如 `SUBI_BFF_001`），两端配置相同密码 |

| 配置位置 | 变量名 |
|----------|--------|
| 培训 `instrument-training-home/.env` | `INTEGRATION_SERVICE_EMPLOYEE_ID` / `INTEGRATION_SERVICE_PASSWORD` |
| Sub-I `subi_knowledge_platform/.env.integration` | `INSTRUMENT_TRAINING_SERVICE_EMPLOYEE_ID` / `INSTRUMENT_TRAINING_SERVICE_PASSWORD` |

**密码变更后必做：**

```bash
cd "$TARGET"
docker compose up -d subi-backend --force-recreate   # 勿仅用 restart
```

**验证服务账号登录：**

```bash
docker exec subi_backend python -c "
import json, os, urllib.request, urllib.error
base = os.environ['INSTRUMENT_TRAINING_API_BASE'].rstrip('/')
data = json.dumps({'employee_id': os.environ['INSTRUMENT_TRAINING_SERVICE_EMPLOYEE_ID'],
  'password': os.environ['INSTRUMENT_TRAINING_SERVICE_PASSWORD']}).encode()
req = urllib.request.Request(base+'/auth/login', data=data,
  headers={'Content-Type':'application/json'}, method='POST')
try:
    with urllib.request.urlopen(req, timeout=10) as r: print('OK', r.status)
except urllib.error.HTTPError as e: print('FAIL', e.code, e.read()[:120])
"
```

### 8.4 高风险：Sub-I 与培训版本不同步

| 项目 | 说明 |
|------|------|
| **风险** | 资质查询报契约错误；人员同步 404（BFF 仍调旧 `/users` 或培训无 `/integrations/users`） |
| **触发条件** | 只更新一个子仓库，或镜像与代码版本不一致 |
| **应对策略** | 三仓库同一次部署；`docker load` 与解压代码来自同一次 `build` |

### 8.5 高风险：宿主机 `8001` 端口被占用（极空间特有）

| 项目 | 说明 |
|------|------|
| **风险** | `subi_backend` 端口映射失败，Sub-I 不可用 |
| **触发条件** | 极空间系统服务 `downloader` 等占用 `8001` |
| **应对策略** | 部署前检查；在根目录 `.env` 设置 `SUBI_API_HOST_PORT=18001`（用户仍访问 `:8510`，容器内部仍为 8001） |

```bash

sed -i 's/^SUBI_API_HOST_PORT=.*/SUBI_API_HOST_PORT=18001/' "$TARGET/.env"
```

### 8.6 中风险：甘特图 `dist/` 未构建

| 项目 | 说明 |
|------|------|

| **触发条件** | 仅 `docker compose restart`；或培训库中服务账号已存在，`bootstrap` 跳过重建 |
| **应对策略** | 改密后 `up -d --force-recreate`；必要时在培训库重置该工号密码与 `.env` 对齐 |

| 项目 | 说明 |
|------|------|
| **风险** | 新 Alembic 迁移失败导致培训后端无法 `/ready` |
| **触发条件** | 培训库损坏或版本跳跃 |
| **应对策略** | 更新前按 §6.3 备份 `instrument_training.db`；失败时从 `BACKUP_DIR` 回滚（§10） |

### 8.9 中风险：离线包/脚本未含新配置

| 项目 | 说明 |
|------|------|
| **风险** | 用旧流程打包部署，缺 `.env` / `.env.integration` / `dist/` |
| **触发条件** | 仅运行 `导出离线部署包.bat` 而未手动补配置文件 |
| **应对策略** | 优先用本文 **方案 C（SSH 传包）**；离线部署须额外拷贝三个 `.env` 文件与 `gantt-chart/dist` |

### 8.10 低风险：Tunnel / Z 盘 / orphan 容器

| 风险 | 应对策略 |
|------|----------|
| `cloudflared` orphan 警告 | 忽略；Tunnel 用单独 compose 启动 |
| Z 盘断开 | 用 SSH 方案 C，不依赖 `Z:\` |
| 外网 Tunnel 未配甘特图 | 内网 `:8520` 仍可用；外网需在 Tunnel 增加 `gantt` → `:8520` |

### 8.11 部署策略推荐顺序（汇总）

```
1. 备份 data / uploads / 现有 .env*
2. 三仓库 git pull 到同一提交
3. 准备 instrument-training-home/.env + subi .env.integration（专用账号，非 3267）
4. 构建 gantt-chart/dist（可选）
5. build + 传包 + NAS 解压 + docker load
6. 检查 8001 → 必要时改 18001
7. docker compose -f docker-compose.yml -f docker-compose.zspace.yml up -d --no-build
8. 验收：/ready 200、服务账号登录 200、8501/8510/8520、资质查询与人员同步
9. 改密后：培训 3267 个人密码与 .env.integration 服务密码分开维护；改服务密码必 force-recreate
```

### 8.12 三份密码分工（避免再混）

| 用途 | 存储位置 | 改密码后需同步 |
|------|----------|----------------|
| 培训系统个人登录（8501） | `instrument_training.db` | 仅影响本人；**不要**当服务账号 |
| Sub-I 个人登录（8510） | `subi_knowledge.db` | 仅影响本人 |
| 资质查询 / 培训同步（BFF） | 培训 `.env` + Sub-I `.env.integration` | **两端必须一致** + `force-recreate subi-backend` |

## 9. 常见问题与处理

### 9.1 `scp` Permission denied（目标为 zfsv3 目录）

**原因：** 普通用户不能写 `/tmp/zfsv3/...`。  
**处理：** 只 `scp` 到 `/tmp/`，`sudo -i` 后再 `tar` 解压到 `TARGET`。

### 9.2 `tar` 解压失败 / 权限不足

**处理：** 必须 `sudo -i` 后再解压；不要在未提权 shell 里操作 `TARGET`。

### 9.3 `docker.sock` permission denied

**处理：** `sudo -i` 后用 root 执行 `docker compose`。

### 9.4 启动失败：`8001` 端口已被占用

```bash
ss -tlnp | grep 8001
# 或
netstat -tlnp | grep 8001
```

常见占用：`downloader`。按 §6.5 在根目录 `.env` 设置 `SUBI_API_HOST_PORT=18001` 后重新 `up -d`。

### 9.5 8501 显示「登录已过期」或无法登录

多为 **401 工号或密码错误**，不是会话过期。培训库已有数据时 **不会** 自动重建默认管理员（见 `instrument-training-home/app/bootstrap.py`）。

**在 NAS 上重置 3267 密码为 `123456`：**

```bash
docker exec instrument_train_backend python -c "
from sqlalchemy import select
from app.database import SessionLocal
from app.core.security import hash_password
from app.models.user import User
db = SessionLocal()
user = db.scalars(select(User).where(User.employee_id == '3267')).first()
if user is None:
    raise SystemExit('user 3267 not found')
user.password_hash = hash_password('123456')
user.must_change_password = True
db.commit()
print('password reset OK for 3267')
"
```

重置后登录，并**尽快在系统内修改为强密码**。

**验证登录 API：**

```bash
curl -s -X POST "http://127.0.0.1:8000/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"employee_id":"3267","password":"123456"}'
```

### 9.6 `cloudflared` orphan 警告

`docker compose up` 提示 orphan containers（`cloudflared`）可**忽略**，不影响四业务容器。Tunnel 需单独 compose 文件启动。

### 9.7 更新后 Sub-I 资质查询失败

按 **§8.3** 检查专用服务账号与 `.env.integration`。常见步骤：

1. 确认 `subi_knowledge_platform/.env.integration` 存在且与培训 `INTEGRATION_SERVICE_*` 一致  
2. `docker compose up -d subi-backend --force-recreate`  
3. 运行 §8.3 服务账号登录验证（期望 `OK 200`）

若误删配置文件，从 `BACKUP_DIR` 恢复：

```bash
cp -a "$BACKUP_DIR/.env" "$TARGET/subi_knowledge_platform/.env" 2>/dev/null || true
cp -a "$BACKUP_DIR/.env.integration" "$TARGET/subi_knowledge_platform/.env.integration" 2>/dev/null || true
cp -a "$BACKUP_DIR/training.env" "$TARGET/instrument-training-home/.env" 2>/dev/null || true
docker compose up -d subi-backend instrument_train_backend --force-recreate
```

### 9.8 Z 盘 `Test-Path` 为 False

先在同一 WiFi 下用极空间客户端重新挂载共享文件夹；**仍建议用 SSH 方案 C**，不依赖 Z 盘。

## 11. 双库与账号说明

- **培训系统**（8501 / 8000）：`instrument_training.db`，工号登录。  
- **Sub-I**（8510 / 容器内部 8001；宿主机 API 默认 8001、极空间可为 18001）：`subi_knowledge.db`，独立用户表。
- Sub-I 查询培训资质 / 人员同步时，通过 **`.env.integration` 专用服务账号**（如 `SUBI_BFF_001`）访问培训 8000，与 3267 个人登录、Sub-I 个人登录均无关。详见 **§8.12**。

更新时**只替换代码和镜像**，不要用开发机上的 `data/*.db` 覆盖 NAS，除非你在做有计划的整库迁移。
