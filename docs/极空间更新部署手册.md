# 极空间更新部署手册

> **用途：** 开发机已验证新版本后，将代码与 Docker 镜像更新到极空间 NAS（**保留业务数据**）。  
> **适用：** 极空间上已有运行中的 `projects` 部署（非首次安装）。  
> **首次离线部署：** 见 [archive/回家部署清单-2026-06-26.md](./archive/回家部署清单-2026-06-26.md)。

## 2. 更新策略对比

| 方案 | 适用 | 说明 |
|------|------|------|
| **A. 离线包** | U 盘 / 文件管理器拷贝 | 运行 `导出离线部署包.bat`，整包拷到 NAS；适合无稳定 SSH |
| **B. Z 盘直拷** | Z 盘稳定挂载时 | 不推荐；挂载不可靠 |
| **C. SSH 传包（推荐）** | 开发机与 NAS 同局域网 | 本机 `build` + `tar` + `scp` 到 NAS `/tmp`，root 解压部署 |

下文以 **方案 C** 为主（2026-07-06 验证通过）。

## 3. 更新前检查

- [ ] 电脑与极空间在**同一局域网**
- [ ] 开发机 **Docker Desktop 已启动**，本地 `docker compose build` 成功
- [ ] 极空间 **SSH 已开启**（设置 → SSH，建议「仅限局域网」）
- [ ] 关闭 Windows 上误开的、指向 NAS 路径的容器（避免在 PC 上起服务）
- [ ] 确认 NAS 上四容器当前可访问（可选，便于对比）

## 4. 阶段 A：开发机打包（PowerShell）

在 **Windows 终端** 执行（工作目录 `D:\projects`）：

```powershell
cd D:\projects

# --- 1) 拉取最新代码（三仓库）---
git pull
Push-Location instrument-training-home; git pull; Pop-Location
Push-Location subi_knowledge_platform; git pull; Pop-Location

# --- 2) 构建镜像 ---
docker compose build
if ($LASTEXITCODE -ne 0) { throw "build failed" }

# --- 3) 导出镜像 tar（自动读取 compose 镜像名）---
$images = @(docker compose config --images 2>$null | Where-Object { $_ -and $_.Trim() })
Write-Host "Images:"; $images | ForEach-Object { Write-Host "  $_" }
docker save -o D:\projects\docker-images-latest.tar @images
if ($LASTEXITCODE -ne 0) { throw "docker save failed" }

# --- 4) 打代码包（排除业务数据与密钥）---
# 在 projects 根目录打包，解压后目录结构不变
tar -czf D:\projects\projects-code.tar.gz `
  --exclude="./instrument-training-home/data" `
  --exclude="./subi_knowledge_platform/data" `
  --exclude="./subi_knowledge_platform/uploads" `
  --exclude="./subi_knowledge_platform/.env" `
  --exclude="./.git" `
  --exclude="./backups" `
  --exclude="./terminals" `
  -C D:\projects .

Get-Item D:\projects\projects-code.tar.gz, D:\projects\docker-images-latest.tar |
  Format-Table Name, @{N='MB';E={[math]::Round($_.Length/1MB,1)}}
```

> **说明：** 不要把手上的旧 `offline-deploy_*` 包当「最新版」——以本次 `git pull` + `build` 产物为准。  
> 若更习惯一键脚本，可用 `导出离线部署包.bat`（选 **跳过业务数据**），再把包内 `projects` 与 `docker-images.tar` 按下面步骤传到 NAS。


输入极空间登录密码（输入时不显示，正常）。

## 6. 阶段 C：极空间部署（root）

### 6.1 连接与提权

```powershell
ssh -p 10000 13816937329@192.168.50.56
```

```bash
sudo -i
```

### 6.2 变量（整段脚本会用到）

```bash
TARGET="/tmp/zfsv3/sata11/13816937329/data/docker/projects"
STAMP=$(date +%Y-%m-%d_%H%M%S)
BACKUP_DIR="/tmp/zfsv3/sata11/13816937329/data/docker/backups/pre_update_$STAMP"
```

### 6.3 备份业务数据（必做）

```bash
mkdir -p "$BACKUP_DIR"
cp -a "$TARGET/instrument-training-home/data/instrument_training.db" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/data/subi_knowledge.db" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/uploads" "$BACKUP_DIR/" 2>/dev/null || true
cp -a "$TARGET/subi_knowledge_platform/.env" "$BACKUP_DIR/" 2>/dev/null || true
ls -la "$BACKUP_DIR"
echo "Backup OK: $BACKUP_DIR"
```

### 6.4 解压代码并加载镜像

```bash
cd "$TARGET"

# 解压代码（覆盖除 data/uploads/.env 外的文件；上述目录未打进包）
tar -xzf /tmp/projects-code.tar.gz -C "$TARGET"

# 加载镜像
docker load -i /tmp/docker-images-latest.tar
```

> 解压与 `docker load` 均需 **root**；普通用户会遇到 `docker.sock` 权限错误或解压失败。

### 6.5 端口：8001 冲突时改为 18001

极空间系统服务 `downloader` 可能占用宿主机 **8001**。Sub-I 后端对外映射需避开：

```bash
cd "$TARGET"
grep -n '8001:8001' docker-compose.yml || true

# 若存在 8001:8001 且 compose up 报端口占用，执行：
sed -i 's/"8001:8001"/"18001:8001"/' docker-compose.yml
```

- 用户仍通过 **8510** 访问 Sub-I 页面，**无需改浏览器地址**。
- `18001` 仅供宿主机调试 API，勿映射到公网。

### 6.6 启动容器

```bash
cd "$TARGET"
docker compose -f docker-compose.yml -f docker-compose.zspace.yml up -d --no-build

sleep 10
docker compose ps
```

`docker-compose.zspace.yml` 会设置 `SUBI_DATA_PROFILE=production`（生产只读保护）。

若已配置 Cloudflare Tunnel，业务容器起来后再启 Tunnel（见 [回家部署清单](./archive/回家部署清单-2026-06-26.md) §3）。

### 6.7 清理临时文件（可选）

```bash
rm -f /tmp/projects-code.tar.gz /tmp/docker-images-latest.tar
```

## 8. 常见问题与处理

### 8.1 `scp` Permission denied（目标为 zfsv3 目录）

**原因：** 普通用户不能写 `/tmp/zfsv3/...`。  
**处理：** 只 `scp` 到 `/tmp/`，`sudo -i` 后再 `tar` 解压到 `TARGET`。

### 8.2 `tar` 解压失败 / 权限不足

**处理：** 必须 `sudo -i` 后再解压；不要在未提权 shell 里操作 `TARGET`。

### 8.3 `docker.sock` permission denied

**处理：** `sudo -i` 后用 root 执行 `docker compose`。

### 8.4 启动失败：`8001` 端口已被占用

```bash
ss -tlnp | grep 8001
# 或
netstat -tlnp | grep 8001
```

常见占用：`downloader`。按 §6.5 改为 `18001:8001` 后重新 `up -d`。

### 8.5 8501 显示「登录已过期」或无法登录

多为 **401 工号或密码错误**，不是会话过期。培训库已有数据时 **不会** 自动重建默认管理员（见 `instrument-training-home/app/bootstrap.py`）。

**在 NAS 上重置 3267 密码为 `123456`：**

```bash
docker exec instrument_train_backend python -c "
from sqlalchemy import select
from app.database import SessionLocal
from app.core.security import hash_password
from app.models.user import User
db = SessionLocal()
user = db.scalars(select(User).where(User.employee_id == '3267')).first()
if user is None:
    raise SystemExit('user 3267 not found')
user.password_hash = hash_password('123456')
user.must_change_password = True
db.commit()
print('password reset OK for 3267')
"
```

重置后登录，并**尽快在系统内修改为强密码**。

**验证登录 API：**

```bash
curl -s -X POST "http://127.0.0.1:8000/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"employee_id":"3267","password":"123456"}'
```

### 8.6 `cloudflared` orphan 警告

`docker compose up` 提示 orphan containers（`cloudflared`）可**忽略**，不影响四业务容器。Tunnel 需单独 compose 文件启动。

### 8.7 更新后 Sub-I 资质查询失败

检查 `subi_knowledge_platform/.env` 是否仍在（更新包排除了 `.env`）。若误删，从 `BACKUP_DIR` 恢复：

```bash
cp -a "$BACKUP_DIR/.env" "$TARGET/subi_knowledge_platform/.env"
docker compose restart subi_backend
```

### 8.8 Z 盘 `Test-Path` 为 False

先在同一 WiFi 下用极空间客户端重新挂载共享文件夹；**仍建议用 SSH 方案 C**，不依赖 Z 盘。

## 9. 回滚

若新版本异常，用 §6.3 的备份恢复数据并回退镜像（需保留旧 `docker-images.tar` 或重新 `load` 旧包）：

```bash
TARGET="/tmp/zfsv3/sata11/13816937329/data/docker/projects"
BACKUP_DIR="/tmp/zfsv3/sata11/13816937329/data/docker/backups/pre_update_YYYY-MM-DD_HHMMSS"  # 换成实际目录

cd "$TARGET"
docker compose down

cp -a "$BACKUP_DIR/instrument_training.db" "$TARGET/instrument-training-home/data/"
cp -a "$BACKUP_DIR/subi_knowledge.db" "$TARGET/subi_knowledge_platform/data/"
cp -a "$BACKUP_DIR/uploads/"* "$TARGET/subi_knowledge_platform/uploads/" 2>/dev/null || true
cp -a "$BACKUP_DIR/.env" "$TARGET/subi_knowledge_platform/.env" 2>/dev/null || true

# 若有旧镜像 tar：
# docker load -i /path/to/old-docker-images.tar

docker compose -f docker-compose.yml -f docker-compose.zspace.yml up -d --no-build
```

## 10. 双库说明

- **培训系统**（8501 / 8000）：`instrument_training.db`，工号登录。  
- **Sub-I**（8510 / 8001）：`subi_knowledge.db`，独立用户表。  
- Sub-I 查询培训资质时，通过 `.env` 中的 **培训服务账号**（默认工号 3267）访问 8000，与 Sub-I 登录用户不是同一套密码。

更新时**只替换代码和镜像**，不要用开发机上的 `data/*.db` 覆盖 NAS，除非你在做有计划的整库迁移。

## 13. 更新流程总览

```
开发机 git pull → docker compose build
  → tar 代码包 + docker save 镜像
  → scp 到 NAS /tmp
  → SSH sudo -i
  → 备份 data/uploads/.env
  → tar 解压到 projects 目录
  → docker load
  → （如需）8001 → 18001
  → compose -f zspace up -d --no-build
  → 内网验收 :8501 / :8510
  → 改密 + 保留 backups
```
