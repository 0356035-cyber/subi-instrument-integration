# 甘特排程

> **用途：** 现场检测排程 SPA 与云同步边界。  
> **落点：** `gantt-chart/`（前端），`subi_knowledge_platform/backend/gantt_routes.py`（云端状态）。  
> **不是** Sub-I 项目日历，也不是培训系统。

**更新日期：** 2026-09-09

## 访问

- 本机：`http://127.0.0.1:8520`
- 工具栏「轴宽」可把时间轴拉到 1×–4×，甘特条使用环节配色（不是类型预设色）。
- 开发：`gantt-chart` 目录 `npm run dev` → `http://127.0.0.1:5173`
- nginx 把 `/api/` 反代到 Sub-I 后端 `:8001`

## 流程编辑

- 项目流程是所有受试者的模板。顺序用拖动手柄或上下箭头调整，必须点「保存并应用」才会重建甘特图。流程编辑器可「清空流程」，管理资源可「清空全部资源」（会同时去掉环节上的占用引用）。不再提供重置示例数据。
- 「导入完整流程」按文本规则拆成环节（一行一个、`→` 连接或 CSV），不调用 AI，不自动定稿。导入后在表格里改资源/锚点再保存。
- 「XXX后 X 分钟」（以及即刻 / 30min 同类写法）表示该检测轮次**第一项**相对锚点开始的时间；同一轮后续环节顺序衔接，不对同一锚点重复计时，避免重叠。检测耗时请另写（如 `产品使用后5分钟 VISIA 8分钟`）；只写偏移时检测耗时按 5 分钟并提示。
- 「类型」来自导入文本中的环节名称（如 TIVI700、临床评估），不再折成内置 visia/tewl 预设；下拉选项是当前流程里已出现的类型。
- 导入（替换）会清空旧资源目录，按本次流程重新生成：每一项一名对应人员（临床评估人员、TIVI700人员等）；仪器另生成同名设备；适应/等待另加等待区。同一仪器在不同访视点共用该仪器和该人员。各类型自动分配颜色。
- 优化好一名受试者后：受试者信息窗「同步流程到项目」，或流程编辑器「从受试者读取」。会更新项目模板，并把相对时间套到同项目其他未完成受试者。
- 新建受试者可选择「复制已有受试者流程」，套用该受试者当前甘特图上的顺序、耗时和相对间隔。

## 云同步

| 方法 | 路径 | 权限 |
|------|------|------|
| GET | `/gantt/health` | 无需登录 |
| GET | `/gantt/state` | 登录用户 |
| PUT | `/gantt/state` | editor / admin / schedule_manager / system_maintainer |

浏览器仍会自动写入 `localStorage`。云端保存/加载是显式操作，使用 Sub-I 工号登录。

## 不要做

- 不要把甘特图并进 Streamlit，也不要并进培训系统。
- 不要用 Git 或重置示例数据恢复业务排程。
- 不要让 AI 在无人核对的情况下自动生成最终临床流程。
