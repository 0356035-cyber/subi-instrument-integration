# 测试环节与项目日历联动

> 用途：说明项目测试环节负责人如何进入项目日历的人员安排。
> 何时读：修改 `ProjectTestStage`、项目日历事件或项目人员安排时。

## 业务规则

- 每个测试环节指定一名项目负责人或项目成员，并关联一个或多个访视节点。
- 测试类型包括临床评估、仪器检测、乳酸试验、自评问卷、产品使用、筛选问卷、知情同意和其他；选择“其他”时必须填写自定义测试环节名称。
- 项目日历存在关联访视节点的事件时，系统为该环节负责人在每个对应时段创建一条人员安排；同一访视日的上午和下午均会生成。
- 自动记录标记为 `source_type = test_stage`，并使用 `source_test_stage_id` 追溯到测试环节。
- 日历页面将自动记录显示为“测试环节”，人工补充记录显示为“人工安排”。
- 人员安排统一显示为“姓名（工号）”；姓名缺失时回退显示工号。
- 同一天、同一时段内的项目日历事件按项目合并显示；项目名称只显示一次，关联访视节点仍作为可独立删除的子项展示。

## 同步边界

- 新增或更新测试环节：仅同步该环节生成的人员安排。
- 删除测试环节：仅删除该环节生成的人员安排。
- 重新同步项目自动日历：重建自动事件和自动人员安排；已有人工安排不删除，只解除与被替换自动事件的关联以保留历史记录。
- 周排班写入的项目岗位属于人工安排，不会覆盖测试环节自动记录。
- 测试环节自动记录不能从项目日历的岗位删除接口直接删除，应回到“测试环节”中维护负责人或访视节点。
- 项目日历事件提供删除确认。自动事件删除后会移除对应自动安排，但下一次重新生成项目日历时会再次出现。

## 冲突预警

- 冲突以“同一人员、同一日期、同一时段、多个项目”为准；上午和下午不会互相误报。
- 项目日历、周排班和项目日历导入完成后的反馈均会显示冲突人员姓名、工号、时段和关联项目。

## 技术落点

- `subi_knowledge_platform/backend/project_test_routes.py`：测试环节新增、更新、删除触发同步。
- `subi_knowledge_platform/backend/schedule_crud.py`：日历同步与自动人员安排维护。
- `subi_knowledge_platform/backend/schedule_migrations.py`：旧数据库增加来源字段，已有记录默认视为人工安排。
- `subi_knowledge_platform/frontend/schedule_calendar.py`：来源标识和人工安排提示。

## 验证范围

- 一个访视节点同步上午、下午两个时段时，均生成负责人安排。
- 修改负责人后，自动记录更新且人工记录保留。
- 重新同步日历或删除测试环节后，仅处理相应自动记录。
