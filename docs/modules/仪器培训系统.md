# 仪器培训系统

> **用途：** `instrument-training-home` 独立系统功能与整合 API。  
> **何时读：** 改培训/考核/授权、整合端点时。  
> **关联：** Sub-I 侧见 [资质整合.md](./资质整合.md)。

---

## 定位

**保持独立，不并入 Sub-I。** 负责人员台账、仪器设备台账、维护校准、**科室培训科目**、培训/考核、**仪器授权**、到期提醒、Excel 导入。

技术栈：Streamlit (:8501) + FastAPI (:8000) + SQLite

业务双轨：

| 轨道 | 对象 | 培训 | 考核 | 授权 |
|------|------|------|------|------|
| 仪器 | `Instrument` | 有 | 有 | **有（原装）** |
| 通用科目 | `TrainingSubject`（挂自定义分类） | 有 | 科目级可选（`requires_assessment`） | **无** |

培训/考核新建时必须且只能关联 **仪器或科目之一**（XOR）。Sub-I 资质整合 API **仅仪器**，科目记录不进入整合响应。

## 主要功能

| 模块 | 说明 |
|------|------|
| 人员管理 | 科室人员；`can_login` 白名单 |
| 仪器管理 | 设备台账（资产编号、分类、厂商、型号、序列号、位置、启用日期、负责人、状态）、重复仪器合并 |
| 维护与校准 | 校准、维护、维修、核查记录；按下次到期日提示已到期、7 天内与提醒范围内事项 |
| 科目目录 | 前端「培训科目」：自定义分类 + 科目；科目可配置是否需要考核；无硬编码预置清单 |
| 培训/考核/授权 | ID 按业务日期重排；多次授权取最新授权日生效；培训/考核可挂仪器或科目 |
| 培训/考核批量登记 | 科室可多选人员；培训使用整批相同信息，考核可为每人分别录入理论、实操成绩和结果；整批校验后统一写入 |
| 人员综合查询 | 仪器资质关联表 + 科目培训/考核概况（无需考核科目不标缺考核） |
| 到期提醒、操作日志、统计报表 | 日常管理 |
| Excel 导入 | 批量导入实验室 Excel |

### 科目目录 API

| 路径 | 说明 |
|------|------|
| `GET/POST /training-subject-categories` | 分类列表 / 创建 |
| `GET/PUT/DELETE /training-subject-categories/{id}` | 分类详情 / 更新 / 删除（有科目时禁止硬删） |
| `GET/POST /training-subjects` | 科目列表 / 创建（可筛 `category_id`、`active_only`、`requires_assessment`） |
| `GET/PUT/DELETE /training-subjects/{id}` | 科目详情 / 更新 / 删除（有培训/考核记录时禁止硬删，应停用） |

### 批量登记 API

| 路径 | 说明 |
|------|------|
| `POST /training-records/batch` | 为多名人员创建相同培训记录；`user_ids` 不可为空或重复；`instrument_id` 与 `subject_id` 必须且只能其一 |
| `POST /assessment-records/batch` | 可沿用整批统一成绩，也可传 `participant_scores` 为每名人员分别提供理论成绩、实操成绩和结果；若挂科目，该科目必须 `requires_assessment=true` |

## 登录白名单

仅配置名单内人员可登录（`instrument-training-home/app/config.py` → `login_allowed_names`）。科室可登记多人，登录权单独控制。

## 生产安全配置

培训后端通过 `instrument-training-home/.env` 接收运行时安全配置。该文件不进入 Git，也被 `.dockerignore` 排除，Compose 仅在容器运行时注入；可从 `.env.example` 创建。

- `APP_ENVIRONMENT=production` 时，必须设置至少 32 位的 `JWT_SECRET`；弱默认值会拒绝启动。
- `CORS_ALLOWED_ORIGINS` 必须是明确的前端来源白名单，不能使用 `*`。
- 空数据库首次初始化管理员须提供 `BOOTSTRAP_ADMIN_PASSWORD`，不再使用内置默认密码。
- Excel 导入新增人员默认不可登录，并生成不可预测密码；管理员需要显式重置密码后才能启用其登录权限。

### Sub-I 专用服务账号

`INTEGRATION_SERVICE_EMPLOYEE_ID` 与 `INTEGRATION_SERVICE_PASSWORD` 同时设置后，培训服务启动迁移完成时会创建专用账号（标记为 `is_service_account`）。该账号只能调用 `/api/v1/integrations/*` 的只读端点，不能访问人员、仪器、培训、考核、授权、导入或操作日志等交互式 API。

切换时须将同一工号和密码同步填入 Sub-I 的 `INSTRUMENT_TRAINING_SERVICE_EMPLOYEE_ID` / `INSTRUMENT_TRAINING_SERVICE_PASSWORD`，再部署两端；不要复用管理员或个人工号。

### 工号生命周期

- `employee_id` 是跨系统关联键，常规人员编辑不得直接修改。
- 管理员只能通过 `POST /users/{user_id}/correct-employee-id` 更正工号，并必须填写原因；系统保留旧值、新值、操作者和时间的不可变审计记录。
- Excel 导入创建的 `XL*` 人员标记为临时工号，默认不可登录，也不会同步到 Sub-I；管理员完成工号更正后才成为正式身份。
- 服务账号工号不可通过该流程更正，避免 BFF 凭据漂移。

### Excel 导入批次审计

非预览导入会记录批次号、操作者、工作表、文件 SHA-256、资质策略版本、写入/跳过计数及问题总数；不保存原始 Excel 内容。操作日志以批次号关联，便于追溯但不扩大敏感文件留存。

### 启动与维护边界

容器常规启动仅执行 Alembic、空库管理员初始化和缺失的专用服务账号创建；不会自动重排培训/考核/授权 ID，也不会按登录白名单改写既有 `can_login`。这两项维护必须由管理员在备份与影响确认后显式执行：`python -m app.maintenance resequence-record-ids` 或 `python -m app.maintenance sync-login-permissions`。

## 整合 API（供 Sub-I）

前缀 `/api/v1`：

| 路径 | 说明 |
|------|------|
| `GET /integrations/qualifications` | 按工号查资质 |
| `GET /integrations/qualifications/by-instrument` | 按仪器查 |
| `GET /integrations/users` | 供 Sub-I 同步的最小人员档案 |
| `GET /users/by-employee-id/{employee_id}` | 按工号查用户 |
| `GET /health` | 健康检查 |

### 设备生命周期数据

- `Instrument.asset_code` 是设备台账的稳定业务编号。既有仪器在迁移时自动补为 `EQ-<原ID>`；后续新建仪器留空时也由系统生成。
- `InstrumentMaintenanceRecord` 记录仪器的校准/维护/维修/核查、执行与下次到期日期、结果、服务方和凭证编号。
- 维护记录随仪器合并迁移到保留的主仪器，不得因去重丢失；操作同时写入操作日志。
- 本阶段不保存校准证书附件，也不向 Sub-I 写入数据。下一阶段由只读整合 API 提供可用仪器目录，再让项目测试环节关联 `instrument_id`。

运行状态端点：

- `GET /health`：进程存活（liveness），不检查数据库。
- `GET /ready`：业务就绪（readiness），仅在数据库可访问且应用已启动完成时返回 `ready`；未就绪时返回 HTTP 503。

Compose 以 `/ready` 作为培训后端健康检查。Sub-I 启动时等待该检查通过；运行期间培训服务不可用时，Sub-I 的主功能继续可用，资质 BFF 返回明确的 `dependency_state=degraded`，不得将其解释为人员资质无效。
