# 权限与用户管理

> **用途：** §14.12 总库分层权限、角色映射、用户同步、主任修改提醒。  
> **何时读：** 改权限、用户管理、资料可见性、项目成员时。  
> **关联：** 数据模型见 [数据模型.md](../数据模型.md) §User/ProjectMember；历史讨论见 [archive/产品讨论§14-归档摘要.md](../archive/产品讨论§14-归档摘要.md)。

**状态：** 一期 MVP 已上线（2026-07-06）

---

## 架构原则

| 原则 | 说明 |
|------|------|
| 总库合并 | 不每人一套子库；用 `project_id`、角色、成员关系区分 |
| role ≠ job_title | 系统权限靠 `User.role`；职务仅展示 |
| 项目负责人 | 靠 `Project.owner_employee_id`，非 `editor` 角色 |

---

## 角色与能力

| `role` | 业务视野 | 用户管理 |
|--------|----------|----------|
| `viewer` | 法规全员可见 + 参与项目只读 + 自己的排班 | — |
| `editor` | 负责人项目可编辑 + 模版/负责人须知（若负责项目） | — |
| `schedule_manager` | **本科室全盘**业务可改 | — |
| `admin` | **全部**业务 + 用户管理 | ✅ |
| `system_maintainer` | **仅自己负责/参与的项目** + 运维；负责项目可申请删除 | ✅ |

## 资料可见性

| 类型 | 谁可看 | 谁可改 |
|------|--------|--------|
| 法规/伦理/培训课件 | 全员 | 负责人 / 主任 / admin |
| 模板下载中心 | 项目负责人及以上 | 同上 |
| 部门内部要求 | 按 `audience_scope` | schedule_manager / admin |
| 最新通告 | 全员可见 | 科室主任（`schedule_manager`）/ 江文才（3223） |
| 项目资料 | 项目成员 | 项目负责人；主任/admin 可改 |

## 主任修改提醒

- `AuditLog` 记录主任/admin 修改非本人负责项目
- `ProjectLeadNotification` + `GET /notifications/pending-changes`
- 前端：登录后待处理变更横幅

---

## 用户管理

- 入口：侧边栏「用户管理」（`admin` / `system_maintainer`）
- 侧边栏「修改密码」；改密后**自动登出**
- `admin` / `schedule_manager` 侧边栏显示近 5 分钟的当前访问人数；只显示汇总数，不显示人员名单
- **培训人员同步：** `POST /users/sync-from-training`
  - 默认**仅新增**用户
  - `?update_existing=true` 才覆盖已有（仍不覆盖 `role`/密码/`is_active`）

## 运营验证

运行脚本（幂等，会创建带 `[权限运营验证]` 标记的样例项目/资料）：

```bat
cd subi_knowledge_platform
set PYTHONPATH=.
set PERM_TEST_PASSWORD=你的当前密码
set HTTP_PROXY=
set HTTPS_PROXY=
.venv\Scripts\python.exe backend\scripts\permission_ops_validation.py
```

**注意：** 验证脚本默认**不会**重置用户密码。此前版本会自动把 3267 改回 `123456`，已修复。

详见 [tasks/权限运营验证.md](../tasks/权限运营验证.md)。
