# 资质整合

> **用途：** Sub-I 与培训系统的 BFF 整合、资质查询页。  
> **何时读：** 改资质查询、BFF 代理、培训 API 对接时。  
> **关联：** 培训侧见 [仪器培训系统.md](./仪器培训系统.md)。

---

## 调用链

```
Sub-I 前端 (:8510) → Sub-I 后端 (:8001) Bearer Token
    → 培训 API (:8000) 服务账号 JWT → instrument_training.db
```

Sub-I 前端**不得**直连 8000。

---

## 环境变量（`subi_knowledge_platform/.env`）

```env
INSTRUMENT_TRAINING_API_BASE=http://localhost:8000/api/v1
INSTRUMENT_TRAINING_SERVICE_EMPLOYEE_ID=3267
INSTRUMENT_TRAINING_SERVICE_PASSWORD=<密码>
INSTRUMENT_TRAINING_TIMEOUT=10
```

该凭据必须对应培训系统的 `is_service_account` 专用账号，仅拥有 `/api/v1/integrations/*` 的只读访问范围；不得使用管理员或个人账号。

## BFF 路由（:8001）

前缀 `/integrations/training`：

- `GET /health`

`GET /health` 返回培训依赖状态：`dependency_state=ready` 表示培训数据库可用；`dependency_state=degraded` 表示仅资质联邦查询不可用。Sub-I 主服务不应因该状态把人员判定为未授权或不合格。
- `GET /instruments`
- `GET /qualifications` — 按工号或姓名精确匹配（姓名解析为唯一工号后查询）
- `GET /qualifications/by-instrument`
- `POST /qualifications/batch-check`

## 资质契约与策略

培训资质响应包含 `contract`：`contract_version=qualification.v1`、`policy_version=qualification-policy.v1`、`evaluated_at`（UTC 判定时点）及状态优先级。Sub-I BFF 只接受已声明支持的契约版本，缺失或不兼容时返回整合错误，不得继续将结果用于资质判断。

`qualification-policy.v1` 的固定语义：最新考核为不通过时状态为「考核未通过」；否则有效授权已过期时为「已过期」；否则存在当前有效授权时为「有效」；无当前有效授权时为「未授权」。`issue_tags` 独立列出缺培训、缺考核等问题项，因此展示或业务决策不得仅凭状态字段忽略问题标签。

仪器列表端点同样要求返回列表。若培训服务返回非列表数据，Sub-I BFF 返回 `TRAINING_CONTRACT_INVALID`（HTTP 502），前端显示可重试的明确错误；不得把异常响应静默解释为空仪器列表。

## 前端

- 侧边栏「项目检测人员授权资质查询」
- `frontend/qualification_inquiry.py`
- 项目详情「人员资质」Tab 嵌入同一面板；先按姓名或工号查询资质，再由负责人决定是否在「成员」Tab 纳入项目成员
- 支持 Excel 导出
