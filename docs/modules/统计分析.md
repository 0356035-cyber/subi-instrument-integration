## 目标

2～3 种最常用标准分析；全程 `log_json` 留痕；可与 SPSS 对照。

---

## 已实现分析类型

| 类型 | 说明 |
|------|------|
| `paired_comparison` | 使用前后配对比较（正态性检验 → 配对 t / Wilcoxon） |
| `change_rate` | 改变率描述统计 |
| `proportion` | 有效率 / 同意率（二项检验 + 95% CI） |

## V2 第一阶段治理能力

流程：选择已确认数据集 → 配置分析参数 → 执行 → `result_json` + `log_json` → 项目负责人提交审核 → 部门主任或科室主任审核。

- `AnalysisTask` 仍是最小可执行单元，不新增独立分析实体。
- 每次执行记录执行人、执行时间与递增的 `analysis_version`。
- 重跑前将当前结果、日志和审核信息追加到 `execution_history_json`；已审核版本不会被静默覆盖。
- 项目负责人由 `Project.owner_employee_id` 识别，可提交审核。
- `admin`（部门主任）和 `schedule_manager`（科室主任）可通过或驳回；权限只使用 `role`，不以 `job_title` 授权。
- 驳回必须填写意见，任务回到草稿；重跑后需要重新提交审核。
- 待审核任务不可重跑；已通过任务可重跑生成新的待审核版本。

## V2 第二阶段 Engine 契约

- `engine/registry.py` 集中注册现有分析类型、标签、必需映射、必需任务字段、必需参数及参数默认值。
- Engine 统一执行顺序为：注册类型解析 → 输入校验 → 参数标准化 → 类型执行器 → 统一结果与日志契约。
- `result_json` 保留原有统计字段和表格，并补充 `schema_version`、`contract_version`、`engine_version` 和 `summary`。
- `log_json` 保留现有数据来源、映射、参数和类型专属日志，并补充 `contract_version`、`engine_version` 和 `input_validation`。
- 本阶段不新增统计方法、数据库实体、API 或页面流程；后续分析类型必须通过同一注册与契约机制接入。

## V2 第三阶段：前后对照与批量分析

- 分析任务对配对比较可选择连续型计量资料或等级资料；资料类型由人工指定，不根据数值格式自动推断。
- 连续型资料输出每个访视的 `n`、Mean、SD，Mean 与 SD 保留两位小数。
- 等级资料输出每个访视的 `n`、Sum、Min、Median、Max；Sum、Min、Max 为整数，Median 保留两位小数。
- 连续型资料先对配对差值执行 Shapiro 正态性检验：通过时使用配对 t 检验，否则使用 Wilcoxon 符号秩检验。
- 等级资料跳过正态性检验，固定使用 Wilcoxon 符号秩检验。
- 显著性水平固定为 `α=0.05`，全部使用双尾检验；Wilcoxon 固定零差值处理与无连续性校正配置，并把配置写入结果与日志，供 SPSS 对照。
- Wilcoxon P 值方法可由任务创建人选择“渐近 P 值”或“精确 P 值”，默认渐近法。精确法在无零差值、无并列绝对秩时使用 SciPy exact；存在零差值或并列绝对秩时改用穷举置换精确法。有效非零配对样本超过 20 时拒绝精确法并要求选择渐近法，避免指数级计算阻塞系统。
- 配对比较支持同一数据集、同一访视、同一资料类型下的多个指标批量执行。每个指标独立计算 P 值，结果不自动合并为临床结论，也不进行多重比较校正。
- `change_rate` 当前仅支持单指标连续型资料；问卷二项检验、组间比较、多组比较、VISIA、OCT 与 PRIMOS 仍待后续单独开发。
