# 统计分析

> **用途：** 阶段 5 Analysis 模块设计与落点。  
> **何时读：** 开发规则引擎、分析任务时。  
> **状态：** ✅ 已完成（2026-07-06）。  
> **关联：** [数据分析规范.md](../数据分析规范.md)、[阶段5-Analysis.md](../tasks/阶段5-Analysis.md)。

---

## 目标

2～3 种最常用标准分析；全程 `log_json` 留痕；可与 SPSS 对照。

---

## 已实现分析类型

| 类型 | 说明 |
|------|------|
| `paired_comparison` | 使用前后配对比较（正态性检验 → 配对 t / Wilcoxon） |
| `change_rate` | 改变率描述统计 |
| `proportion` | 有效率 / 同意率（二项检验 + 95% CI） |

---

## 约束

- 仅 `status=已确认` 的 Dataset 可用于分析
- `proportion` 类型需在 `parameters_json` 中提供 `threshold` 与 `success_rule`
- 已执行任务需先「驳回」才能修改参数

## V2 第一阶段治理能力

流程：选择已确认数据集 → 配置分析参数 → 执行 → `result_json` + `log_json` → 项目负责人提交审核 → 部门主任或科室主任审核。

- `AnalysisTask` 仍是最小可执行单元，不新增独立分析实体。
- 每次执行记录执行人、执行时间与递增的 `analysis_version`。
- 重跑前将当前结果、日志和审核信息追加到 `execution_history_json`；已审核版本不会被静默覆盖。
- 项目负责人由 `Project.owner_employee_id` 识别，可提交审核。
- `admin`（部门主任）和 `schedule_manager`（科室主任）可通过或驳回；权限只使用 `role`，不以 `job_title` 授权。
- 驳回必须填写意见，任务回到草稿；重跑后需要重新提交审核。
- 待审核任务不可重跑；已通过任务可重跑生成新的待审核版本。
