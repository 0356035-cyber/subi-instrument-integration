# 统计分析

> **用途：** 阶段 5 Analysis 模块设计与落点。  
> **何时读：** 开发规则引擎、分析任务时。  
> **状态：** ✅ 已完成（2026-07-06）。  
> **关联：** [数据分析规范.md](../数据分析规范.md)、[阶段5-Analysis.md](../tasks/阶段5-Analysis.md)。

---

## 目标

2～3 种最常用标准分析；全程 `log_json` 留痕；可与 SPSS 对照。

---

## 已实现分析类型

| 类型 | 说明 |
|------|------|
| `paired_comparison` | 使用前后配对比较（正态性检验 → 配对 t / Wilcoxon） |
| `change_rate` | 改变率描述统计 |
| `proportion` | 有效率 / 同意率（二项检验 + 95% CI） |
| `demographic_summary` | 年龄与性别的人口学描述统计 |

```
backend/analysis/
├── routes.py

├── migrations.py
└── engine/

frontend/analysis_pages.py
```

流程：选择已确认数据集 → 配置分析参数 → 执行 → `result_json` + `log_json` → 人工审核（驳回后可修改）

自动分析流程：遍历全部已确认数据集 → 仅对含 `BL` 的数据集，将每个其他访视与 `BL` 配对 → 系统按指标名称分为连续型资料与等级资料 → 创建并执行批量配对任务 → `result_json` + `log_json` → 人工审核。

固定格式仪器自动整理生成的 `GLOSS`、`Sebum`、`SEr`、`SEsc`、`SEsm`、`SEw` 及 VISIA 汇总表中的连续型指标均进入上述流程；有 `BL` 和后续访视时，自动分析会按既有规则与 `BL` 配对，原始仪器文件和派生数据集的来源关系保留在处理日志中。

## 约束

- `proportion` 类型需在 `parameters_json` 中提供 `threshold` 与 `success_rule`

## V2 第一阶段治理能力

流程：选择已确认数据集 → 配置分析参数 → 执行 → `result_json` + `log_json` → 项目负责人提交审核 → 部门主任或科室主任审核。

- `AnalysisTask` 仍是最小可执行单元，不新增独立分析实体。
- 每次执行记录执行人、执行时间与递增的 `analysis_version`。
- 重跑前将当前结果、日志和审核信息追加到 `execution_history_json`；已审核版本不会被静默覆盖。
- 项目负责人由 `Project.owner_employee_id` 识别，可提交审核。
- 项目负责人可一键提交同一 Project 内全部“已执行且未提交审核”的 AnalysisTask；待审核、已通过、草稿或已驳回任务保持原状态，并逐项保留提交审核审计记录。
- `admin`（部门主任）和 `schedule_manager`（科室主任）可通过或驳回；权限只使用 `role`，不以 `job_title` 授权。
- 驳回必须填写意见，任务回到草稿；重跑后需要重新提交审核。
- 待审核任务不可重跑；已通过任务可重跑生成新的待审核版本。

## V2 第二阶段 Engine 契约

- `engine/registry.py` 集中注册现有分析类型、标签、必需映射、必需任务字段、必需参数及参数默认值。
- Engine 统一执行顺序为：注册类型解析 → 输入校验 → 参数标准化 → 类型执行器 → 统一结果与日志契约。
- `result_json` 保留原有统计字段和表格，并补充 `schema_version`、`contract_version`、`engine_version` 和 `summary`。
- `log_json` 保留现有数据来源、映射、参数和类型专属日志，并补充 `contract_version`、`engine_version` 和 `input_validation`。
- 本阶段不新增统计方法、数据库实体、API 或页面流程；后续分析类型必须通过同一注册与契约机制接入。

## V2 第三阶段：前后对照与批量分析

- 分析任务对配对比较可选择连续型计量资料或等级资料；资料类型由人工指定，不根据数值格式自动推断。
- 连续型资料输出每个访视的 `n`、Mean、SD，Mean 与 SD 保留两位小数。
- 连续型前后配对比较同时输出配对差值的 Mean±SD 及改变率 Mean±SD（`(对比值 - 基线值) / 基线值 × 100%`）；基线值为 0 的配对不进入改变率汇总，并在结构化结果中记录排除数。
- 连续型资料的 Mean、SD、配对差值和改变率始终按原始精度计算，结果展示保留两位小数。Shapiro、配对样本 t 检验和 Wilcoxon 符号秩检验则按任务的 `statistical_decimal_places` 取舍后计算，默认保留两位小数；手动任务可选择 0-6 位小数或原始精度。任务参数、结果配置和执行日志均保留该精度规则，确保可与 SPSS 使用相同精度复现。
- 等级资料输出每个访视的 `n`、Sum、Min、Median、Max；Sum、Min、Max 为整数，Median 保留两位小数。
- 连续型资料先对配对差值执行 Shapiro 正态性检验：通过时使用配对 t 检验，否则使用 Wilcoxon 符号秩检验。
- 等级资料跳过正态性检验，固定使用 Wilcoxon 符号秩检验。
- 显著性水平固定为 `α=0.05`，全部使用双尾检验；Wilcoxon 固定零差值处理与无连续性校正配置，并把配置写入结果与日志，供 SPSS 对照。
- P 值统一保留三位小数；其他连续型计算结果保留两位小数。
- Wilcoxon P 值方法可由任务创建人选择“渐近 P 值”或“精确 P 值”，默认渐近法。精确法使用动态规划计算符号秩的精确分布，支持零差值（按 `wilcox` 规则剔除）和并列绝对秩；不再设置 20 个有效非零配对样本的固定上限。系统设置状态空间与单项计算时限保护，超过保护范围时保留草稿并提示人工在手动分析中选择渐近或 Monte Carlo 方法，不自动降级。
- 配对比较支持同一数据集、同一访视、同一资料类型下的多个指标批量执行。每个指标独立计算 P 值，结果不自动合并为临床结论，也不进行多重比较校正。
- 自动前后配对分析不要求逐项选择统计方法或数据集：遍历全部已确认数据集，固定以 `BL` 为基线，每个其他访视各自与 `BL` 比较。名称含“临床评估”或“乳酸刺痛”的指标识别为等级资料，其余指标识别为连续型资料；两类指标分别生成批量任务。自动任务固定 `α=0.05`、双尾及 Wilcoxon 精确 P 值，并将固定规则写入 `parameters_json` 与 `log_json`。自动前后配对按指标各建一条任务，该任务包含相对 `BL` 的全部对比访视；再次自动分析时更新同一任务，不再按访视拆成多条。未提交审核的旧“一访视一任务”记录会在自动分析时清理。页面可选择“重新执行已有自动分析”，此时覆盖当前结果并重置审核状态，旧结果写入执行历史。不勾选时仍跳过已存在任务。精确计算达到状态空间或时限保护时，任务保持草稿并提示人工改用手动分析，不会静默改为渐近 P 值。
- Analysis 页面将已执行的自动任务汇为“自动分析结果汇总”，按数据集、指标和访视时间顺序展示各对比访视的描述统计、方法与 P 值。新结果表含“对比访视”列；旧结果表仍可读取。P 值统一格式化为三位小数。
- 已执行但未提交审核的任务支持删除或重跑；项目负责人可提交审核。待审核和已通过审核的任务不允许删除，以保护审核流程与审计留痕。
- `change_rate` 当前仅支持单指标连续型资料；组间比较、多组比较、VISIA 图像或设备原始文件、OCT 与 PRIMOS 仍待后续单独开发。固定 VISIA 汇总表的结构化指标已可使用常规连续型前后配对分析。

### 受试者信息与自我评估问卷

- 项目分析人群以人口学表中的正式试验编号建立；人工排除研究号在项目级保存。每次执行人口学、问卷、仪器或其他已映射 `subject_id` 的分析时，系统先按正式试验名册筛选，再排除人工研究号，并把筛选前后人数写入 `log_json`。问卷访视是否完整只影响该项分析的有效样本，不作为项目最终分析人群的判定条件。
- 自动人口学汇总读取受控人口学数据集：年龄输出 Mean±SD（1 位小数）及 Min、Max（整数）；性别按人数和构成比输出。
- 自动自我评估问卷仅处理受控问卷数据集，每个问卷数据集一条任务，结果表按访视列出题目有效率：4-5 分为有效、1-3 分为无效、理论比例 0.67、双尾精确二项检验。其他访视的题目或全空题目不生成 `N=0` 结果。
- 从任务详情点击自动问卷任务的“重跑分析”时，也必须先恢复历史数据集的访视题序并刷新该访视的实际题目范围；不得沿用旧的全局题目列表。
- 问卷结果输出 N、有效数、无效数、有效率、95% CI 与 P 值；P 值显示 3 位小数，结果汇总按临床访视时间顺序展示，同一访视内保持原始文件题目从左到右顺序；任务参数、来源数据集和计算规则均写入结果与日志。
- 手动有效率/同意率分析支持选择一个或多个题目，并可调整阈值、判定规则和理论比例；自动规则只是默认值，不代替人工审核。
