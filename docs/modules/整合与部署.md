## 日常脚本

中文脚本是给日常双击使用的入口；英文脚本通常承载实际逻辑或被中文脚本转调。维护时优先阅读英文脚本与 `scripts/` 下 PowerShell / Python 实现，不要随意删除中文包装脚本。

| 场景 | 脚本 |
|------|------|
| 每天开机 | `启动系统.bat` |
| 关机前备份 | `备份数据.bat` |
| 换机恢复 | `恢复数据.bat` |
| 定时备份（极空间推荐） | `安装定时备份.bat`（每日 02:00，保留 14 份） |
| 数据安全校验 | `verify-data-safety.bat` |
| 安装 Git 防误提交钩子 | `setup-git-hooks.bat` |

### 脚本入口关系

| 日常入口 | 实际逻辑入口 | 说明 |
|----------|--------------|------|
| `启动系统.bat` | `start-docker.bat` → `scripts/start-docker.ps1` | Docker 四容器启动与健康检查 |
| `启动系统-极空间.bat` | `start-docker-zspace.bat` → `scripts/start-docker.ps1 -Mode zspace` | 极空间兼容启动 |
| `启动Tunnel.bat` | `start-tunnel.bat` → `scripts/start-docker.ps1 -Mode tunnel` | Docker + Cloudflare Tunnel |
| `备份数据.bat` | `backup-data.bat` → `scripts/data_safety.py` | 在线备份 SQLite 与 uploads |
| `恢复数据.bat` | `restore-data.bat` | 从 backups 恢复数据库与 uploads |
| `安装定时备份.bat` | `install-scheduled-backup.bat` | 创建 Windows 计划任务 |
| `卸载定时备份.bat` | `uninstall-scheduled-backup.bat` | 删除 Windows 计划任务 |
| `导出离线部署包.bat` | `export-offline-package.bat` → `scripts/export-offline-package.ps1` | 离线包导出 |
| `离线部署.bat` | `deploy-offline.bat` → `scripts/deploy-offline.ps1` | 离线机部署 |

### 脚本风险分级

| 等级 | 脚本 / 命令 | 风险说明 | 执行要求 |
|------|-------------|----------|----------|
| 只读 / 低风险 | `verify-data-safety.bat` | 读取 Git 跟踪状态、备份与 SQLite 完整性；不应修改业务数据 | 可作为人工确认后的安全检查 |
| 启动与构建 / 中风险 | `启动系统.bat`、`start-docker.bat`、`start-tunnel.bat`、`start-docker-zspace.bat` | 会启动/重启容器、构建镜像，可能触发启动迁移；缺少 `subi_knowledge_platform/.env` 时启动脚本可能自动创建默认文件 | 执行前说明影响并等待用户确认 |
| 备份 / 中风险 | `备份数据.bat`、`backup-data.bat`、`scheduled-backup.bat` | 读取真实数据库和 uploads，写入 `backups/`；不会覆盖现库 | 执行前说明会读取业务数据并生成备份 |
| 恢复 / 高风险 | `恢复数据.bat`、`restore-data.bat` | 会覆盖当前 `instrument_training.db`、`subi_knowledge.db` 和 `uploads/`；虽会创建 `pre_restore_*` 安全副本，仍属于高风险操作 | 必须用户明确确认备份目录与风险后才能执行 |
| 配置 / 中风险 | `setup-git-hooks.bat`、`install-scheduled-backup.bat`、`uninstall-scheduled-backup.bat` | 修改 Git hooksPath 或 Windows 计划任务 | 执行前说明会修改本机配置 |

注意：只读健康检查阶段不运行上述脚本，只阅读文档和确认文件/目录是否存在。

## 数据路径（不提交 Git）

| 数据 | 路径 |
|------|------|
| 培训库 | `instrument-training-home/data/instrument_training.db` |
| Sub-I 库 | `subi_knowledge_platform/data/subi_knowledge.db` |
| 附件 | `subi_knowledge_platform/uploads/` |
| Tunnel Token | `.env.tunnel` |

**同步原则：** 代码 `git pull`；业务数据 `备份数据.bat` → 拷贝 `backups/` → `恢复数据.bat`

只读检查规则：

- `.env`、`.env.tunnel`、`subi_knowledge_platform/.env` 只检查是否存在，不打印、不复制、不解析真实内容。
- `data/`、`uploads/`、`backups/` 只检查目录是否存在，不枚举敏感文件细节，不读取内容。

**数据安全（必读）：**

- 业务库**永不进 Git**；禁止 `git checkout -- data/*.db`
- `restore-data.bat` / `恢复数据.bat` 会覆盖数据库和 `uploads/`，必须由用户确认后执行
- 备份使用 SQLite 在线备份 + `PRAGMA integrity_check` 校验（`scripts/data_safety.py`）
- **隔离恢复演练：** `restore-data.bat --target-root D:\projects-restore-drill --backup-root D:\projects\backups`。执行前须在目标目录准备同版本、干净的代码副本和独立 Compose 端口；`--target-root` 必须不是当前项目根目录。恢复后仅在隔离目录启动并验证，禁止将演练恢复到现网目录。
- 极空间部署：`docker-compose.zspace.yml` 自动设 `SUBI_DATA_PROFILE=production`，冒烟/验证脚本默认不可写库
- 开发机：`SUBI_DATA_PROFILE=dev`（见 `subi_knowledge_platform/.env.example`）

### 数据库变更发布门禁

- 培训系统表结构变更必须提供新的 Alembic revision，并在隔离库验证 `alembic upgrade head` 可重复执行；不得手工修改 `.db`。
- Sub-I 表结构变更必须新增或扩展所属域的幂等 `ensure_*` 迁移函数，并提供空库与已有表的隔离验证；不得把破坏性 DDL 放入启动路径。
- 每次涉及数据库结构的发布，先完成可用备份校验，再构建并启动服务，最后检查培训 `/ready`、Sub-I `/health` 及受影响业务路径。
- 历史 JSON、状态和结果记录只做兼容读取或显式映射，不批量覆写既有业务数据；需要数据修复时另立任务并取得确认。
- 恢复演练验收至少包括：两份数据库完整性校验、uploads 可访问性、四容器健康检查，以及不使用演练数据覆盖现网的确认。

## 极空间 NAS + Cloudflare Tunnel

- 内网示例：`http://<NAS_IP>:8501`、`http://<NAS_IP>:8510`
- 外网：`https://train.域名`、`https://subi.域名`
- Token：`cp .env.tunnel.example .env.tunnel`
- 启动：`启动Tunnel.bat`

极空间通常**无 git**：从开发机打包代码与镜像 → SSH 传到 `/tmp` → root 解压并 `docker load` → `up -d`。**勿覆盖 data/、uploads/、`.env`。**

API 8000/8001 **不暴露**到外网。宿主机 8001 若被系统占用，在项目根目录 `.env` 设 `SUBI_API_HOST_PORT=18001`（页面仍用 :8510，详见 [极空间更新部署手册.md](../极空间更新部署手册.md) §8.5）。
