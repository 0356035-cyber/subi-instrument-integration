# 框架整理与加固-第三轮

> **状态：** 已完成
> **类型：** 框架维护 / 数据安全治理
> **边界：** 不开发业务功能，不执行备份或恢复，不读取数据库或真实配置，不修改业务数据。

## 背景

项目的两个 SQLite 数据库使用不同的迁移机制，且业务附件与数据库必须与代码仓库分离。已有备份、恢复和完整性校验能力，但发布门禁和恢复演练要求需要以统一规则固定下来。

## 已完成

- 明确培训系统 Alembic 与 Sub-I `ensure_*` 增量迁移的适用边界。
- 规定数据库变更的隔离验证、备份确认、健康检查与兼容读取要求。
- 明确隔离恢复演练必须使用独立代码副本、目录和端口，禁止覆盖现网目录。
- 扩展 `verify-data-safety.bat`：同时检查两个子仓的 Git 数据隔离、两份实时数据库，以及最新备份中的两份数据库完整性。

## 验收标准

- `verify-data-safety.bat` 的静态检查覆盖 `subi_knowledge_platform` 与 `instrument-training-home`。
- 迁移与恢复规则已同步至开发规范和整合部署文档。
- 未执行任何备份、恢复、迁移或数据库写入操作。

## 后续

- 隔离恢复演练需要用户单独确认备份来源、目标目录、端口和停机影响后执行。
- 生产发布前应人工运行数据安全校验，并保留本次发布所用备份的记录。
