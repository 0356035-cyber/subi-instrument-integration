# 框架整理与加固-第二轮

> **状态：** 进行中  
> **类型：** 框架维护 / 只读健康检查体系  
> **边界：** 不开发新功能，不修改业务逻辑，不启动服务，不运行测试，不写数据库，不读取真实配置内容。

---

## 背景

第一轮已完成 Codex 规则入口、脚本风险分级、测试风险分类和 `.gitignore` 卫生修复。本轮建立“只读健康检查”文档流程，让未来 Codex 在不启动、不写入、不修改配置的前提下快速判断项目现场是否正常。

---

## 目标

- 建立 `docs/只读健康检查.md` 作为主文档。
- 在入口文档中索引只读检查流程。
- 明确安全只读、谨慎只读、未确认禁止运行的命令边界。
- 明确 `.env` 只检查存在，不打印、不复制、不解析真实内容。
- 明确 `data/`、`uploads/`、`backups/` 只检查目录存在，不枚举敏感文件细节。
- 明确 Git `dubious ownership` 只记录现象，不自动处理。

---

## 修改范围

允许修改：

- `README_FOR_CODEX.md`
- `AGENTS.md`
- `docs/开发规范.md`
- `docs/代码地图.md`
- `docs/modules/整合与部署.md`
- `docs/只读健康检查.md`
- `docs/tasks/框架整理与加固-第二轮.md`

禁止修改：

- 业务代码
- 数据库结构
- `docker-compose*.yml`
- 启动、备份、恢复脚本
- 自动化检查脚本
- `data/`
- `uploads/`
- `backups/`
- `.env` / `.env.tunnel`
- SQLite `.db` 文件

---

## 风险控制

- 不运行 Docker。
- 不启动服务。
- 不运行 pytest。
- 不运行冒烟脚本。
- 不运行备份或恢复脚本。
- 不处理 Git `safe.directory`。
- 不提交 Git。
- 只做文档内容验证和 `git status --short`。

## 验证方式

- 检查 `docs/只读健康检查.md` 是否存在并包含检查流程、命令分级和禁止边界。
- 检查入口文档是否已索引只读健康检查。
- 运行 `git status --short` 确认变更范围。

---

## 后续建议

- 若未来需要自动化只读检查脚本，必须另行确认，且脚本不得读取 `.env` 内容或枚举业务附件。
- 若需要处理子仓 Git `dubious ownership`，必须由用户确认后再配置 `safe.directory`。
