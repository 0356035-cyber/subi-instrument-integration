## 1. 系统定位

部门内部管理系统，服务皮肤与化妆品研究室 Sub-I 团队。

| 系统 | 定位 |
|------|------|
| **Sub-I 临床研究资料库** | 法规/模版/项目资料、项目管理、排班、资质查询 |
| **仪器培训与授权系统** | 人员培训、考核、仪器授权及到期管理 |

**不是完整 LIMS。** 系统负责「找得到、挂得住、追得回、排得清」；Word / Excel / SPSS 负责专业撰写与统计，定稿回系统归档。

         │                            │
         │◄────── 服务账号 JWT ─────────┘

### 设计要点

- Sub-I 前端**只访问 8001**，不直连培训 8000
- 培训服务账号仅存 `subi_knowledge_platform/.env`
- 人员以 **工号 `employee_id`** 关联
- 资料多版本以 **`document_group_id`** 归组

## 4. 核心业务流程

### 4.1 资料归档

上传 → 分类 / `document_type` / `audience_scope` → 版本组管理 → 对比与下载 → 可挂 `project_id`

### 4.2 项目管理

建项目 → 设负责人 `owner_employee_id` → 添加成员 → 项目 8 Tab 集中管理资料/排期/资质

### 4.3 排班与日历

访视模板 → 项目访视节点 → 同步日历事件 → 周排班填报 → 冲突预警与资质提示

### 4.3.1 每日记录与月报

周排班拉取当天工作内容 → 手填完成情况/数量 → 按项目或相同内容合并为个人月报 → 下月计划、问题与周末加班手写补充

### 4.4 资质查询

Sub-I 前端 → BFF（8001）→ 培训 API（8000）→ 聚合培训/考核/授权

### 4.5 权限控制

总库合并，靠 `User.role` + 项目关系（`owner_employee_id` / `ProjectMember`）+ 资料 `audience_scope` 控制可见与可改。详见 [modules/权限与用户管理.md](./modules/权限与用户管理.md)。

## 5. 模块关系（以 Project 为中心）

```
Project 项目
├── Documents        项目资料（含通用库 project_id 可空）
├── Schedule         访视节点、日历、周排班
├── Worklogs         每日实绩与个人月报（可选挂 project_id；主入口在侧边栏）
├── Staff            成员 + 资质（BFF 联邦查询）
├── Datasets         已实现：Excel 数据集
├── Analysis         已实现：统计任务与审核
├── Reports          6A/6B：工作台与 Word 草稿；审核归档未开始
└── AI Workspace     【规划】理解 Protocol/SAP
```

通用资料库侧边栏入口**保留**，与项目 Tab 并存（过渡期）。

## 7. 产品边界

**不做：** 完整 LIMS、拖拽甘特图、每人独立子库、培训并入 Sub-I。

**外用分工：**

| 能力 | 归属 |
|------|------|
| 项目运营、资料归档、排班、审计 | 本系统 |
| Word 排版定稿 | Microsoft Word |
| 复杂统计 | SPSS / GraphPad / R |
| 培训/考核/授权台账 | instrument-training-home |
